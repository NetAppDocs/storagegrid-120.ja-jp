= StorageGRID でのクラウドストレージプールのトラブルシューティング
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
クラウドストレージプールの作成、編集、または削除時に発生する可能性のあるエラーを解決するには、以下のトラブルシューティング手順をご利用ください。



[[determine-if-an-error-has-occurred]]
== エラーが発生したかどうかを確認します。

StorageGRID は、既知のオブジェクトを読み取ることで各クラウドストレージプールに対して簡単なヘルスチェックを実行し `x-ntap-sgws-cloud-pool-uuid`、クラウドストレージプールにアクセスでき、正しく機能していることを確認します。StorageGRID がエンドポイントでエラーを検出した場合、各ストレージノードから1分ごとにヘルスチェックを実行します。エラーが解消されると、ヘルスチェックは停止します。ヘルスチェックで問題が検出された場合、ストレージプールページのクラウドストレージプールテーブルの「最後のエラー」列にメッセージが表示されます。

この表は、各クラウドストレージプールで検出された最新のエラーと、そのエラーが発生した時期を示しています。

さらに、ヘルスチェックによって過去5分以内に1つ以上の新しいクラウドストレージプールエラーが発生したことが検出された場合、「クラウドストレージプール接続エラー」アラートがトリガーされます。このアラートに関するメール通知を受け取った場合は、ストレージプールページ（*ILM* > *ストレージプール*を選択）に移動し、「最後のエラー」列のエラーメッセージを確認して、以下のトラブルシューティングガイドラインを参照してください。



[[check-if-an-error-has-been-resolved]]
== エラーが解決されたかどうかを確認する

根本的な問題を解決した後、エラーが解消されたかどうかを確認できます。クラウドストレージプールページからエンドポイントを選択し、*エラーをクリア*を選択します。確認メッセージは、StorageGRID がクラウドストレージプールのエラーを解消したことを示します。

根本的な問題が解決されれば、エラーメッセージは表示されなくなります。ただし、根本的な問題が解決されていない場合（または別のエラーが発生した場合）、数分以内に「最後のエラー」列にエラーメッセージが表示されます。



[[error-health-check-failed-error-from-endpoint]]
== エラー：ヘルスチェックに失敗しました。エンドポイントからのエラー

Amazon S3 バケットでクラウドストレージプールとして使用を開始した後に、デフォルトの保持期間を設定した S3 オブジェクトロックを有効にすると、このエラーが発生する可能性があります。このエラーは、PUT 操作に `Content-MD5`などのペイロードチェックサム値を含む HTTP ヘッダーがない場合に発生します。このヘッダー値は、S3 オブジェクトロックが有効になっているバケットへの PUT 操作に対して AWS が要求するものです。

この問題を解決するには、変更を加えずにlink:editing-cloud-storage-pool.html["クラウドストレージプールを編集する"]の手順に従ってください。この操作により、クラウドストレージプール構成の検証がトリガーされ、クラウドストレージプールエンドポイント構成の S3 オブジェクトロックフラグが自動的に検出および更新されます。



[[error-this-cloud-storage-pool-contains-unexpected-content]]
== エラー：このクラウドストレージプールには予期しないコンテンツが含まれています

クラウドストレージプールを作成、編集、または削除しようとした際に、このエラーが発生する場合があります。バケットまたはコンテナに `x-ntap-sgws-cloud-pool-uuid`マーカーファイルが含まれているにもかかわらず、そのファイルに期待されるUUIDを含むメタデータフィールドが存在しない場合、このエラーが発生します。

通常、このエラーは、新しいクラウドストレージプールを作成しようとしているときに、別の StorageGRID インスタンスがすでに同じクラウドストレージプールを使用している場合にのみ表示されます。

問題を解決するには、以下のいずれかの手順を試してください。

* 新しいクラウドストレージプールを設定していて、バケットに `x-ntap-sgws-cloud-pool-uuid`ファイルと次の例のような追加のオブジェクトキーが含まれている場合は、新しいバケットを作成し、代わりにその新しいバケットを使用してください。
+
追加オブジェクトキーの例： `my-bucket.3E64CF2C-B74D-4B7D-AFE7-AD28BC18B2F6.1727326606730410`

*  `x-ntap-sgws-cloud-pool-uuid`ファイルがバケット内の唯一のオブジェクトである場合は、このファイルを削除してください。


これらの手順がお客様の状況に当てはまらない場合は、サポートにお問い合わせください。



[[error-could-not-create-or-update-cloud-storage-pool-error-from-endpoint]]
== エラー：クラウドストレージプールを作成または更新できませんでした。エンドポイントからのエラー

次のような状況で、このエラーが発生する可能性があります：

* クラウドストレージプールを作成または編集しようとしたとき。
* 新しいクラウドストレージプールの設定時に、S3 Object Lockでサポートされていないプラットフォーム、認証、またはプロトコルの組み合わせを選択した場合。link:../ilm/considerations-for-cloud-storage-pools.html["クラウドストレージプールに関する考慮事項"]を参照してください。


このエラーは、接続または構成の問題により、StorageGRID がクラウドストレージプールへの書き込みを実行できないことを示しています。

この問題を解決するには、エンドポイントからのエラーメッセージを確認してください。

* エラーメッセージに `Get _url_: EOF`が含まれている場合は、Cloud Storage Poolに使用されるサービスエンドポイントが、HTTPSを必要とするコンテナまたはバケットに対してHTTPを使用していないことを確認してください。
* エラーメッセージに `Get _url_: net/http: request canceled while waiting for connection`が含まれている場合は、ネットワーク構成によってストレージノードがクラウドストレージプールで使用されるサービスエンドポイントにアクセスできることを確認してください。
* エラーの原因がサポートされていないプラットフォーム、認証、またはプロトコルにある場合は、S3 Object Lock をサポートする構成に変更し、新しいクラウドストレージプールを再度保存してください。
* その他のエンドポイントエラーメッセージについては、以下のいずれか、または複数を試してください。
+
** クラウドストレージプールに入力した名前と同じ名前の外部コンテナまたはバケットを作成し、新しいクラウドストレージプールを再度保存してみてください。
** クラウドストレージプールに指定したコンテナ名またはバケット名を修正し、新しいクラウドストレージプールを再度保存してみてください。






[[error-failed-to-parse-ca-certificate]]
== エラー：CA証明書の解析に失敗しました

クラウドストレージプールを作成または編集しようとした際に、このエラーが発生する場合があります。このエラーは、クラウドストレージプールの設定時に入力した証明書を StorageGRID が解析できなかった場合に発生します。

この問題を解決するには、提供された認証局（CA）証明書に問題がないか確認してください。



[[error-a-cloud-storage-pool-with-this-id-was-not-found]]
== エラー：このIDを持つクラウドストレージプールが見つかりませんでした

クラウドストレージプールを編集または削除しようとした際に、このエラーが発生する場合があります。このエラーは、エンドポイントが404応答を返した場合に発生します。404応答とは、以下のいずれかを意味します：

* クラウドストレージプールに使用されている認証情報には、バケットに対する読み取り権限がありません。
* クラウドストレージプールに使用されるバケットには、 `x-ntap-sgws-cloud-pool-uuid`マーカーファイルが含まれていません。


問題を解決するには、以下の手順を1つ以上試してください。

* 設定されたアクセスキーに関連付けられているユーザーが、必要な権限を持っていることを確認してください。
* 必要な権限を持つ認証情報を使用して、クラウドストレージプールを編集します。
* 権限設定が正しい場合は、サポートにお問い合わせください。




[[error-could-not-check-the-content-of-the-cloud-storage-pool-error-from-endpoint]]
== エラー：クラウドストレージプールの内容を確認できませんでした。エンドポイントからのエラー

クラウドストレージプールを削除しようとした際に、このエラーが発生する場合があります。このエラーは、何らかの接続または設定の問題により、StorageGRID がクラウドストレージプールバケットの内容を読み取れないことを示しています。

この問題を解決するには、エンドポイントからのエラーメッセージを確認してください。



[[error-objects-have-already-been-placed-in-this-bucket]]
== エラー：このバケットには既にオブジェクトが配置されています

クラウドストレージプールを削除しようとした際に、このエラーが発生する場合があります。ILMによって移動されたデータ、クラウドストレージプールを設定する前にバケットに存在していたデータ、またはクラウドストレージプールの作成後に他のソースによってバケットに格納されたデータが含まれている場合、クラウドストレージプールを削除することはできません。

問題を解決するには、以下の手順を1つ以上試してください。

* 「クラウドストレージプールオブジェクトのライフサイクル」のオブジェクトを StorageGRID に戻す手順に従ってください。
* 残りのオブジェクトがILMによってクラウドストレージプールに配置されたものではないと確信できる場合は、バケットからオブジェクトを手動で削除してください。
+

NOTE: ILMによってクラウドストレージプールに配置された可能性のあるオブジェクトを、手動で削除しないでください。後で手動で削除したオブジェクトにStorageGRIDからアクセスしようとすると、削除されたオブジェクトは見つかりません。





[[error-proxy-encountered-an-external-error-while-trying-to-reach-the-cloud-storage-pool]]
== エラー：プロキシ サーバがクラウド ストレージ プールにアクセスしようとした際に外部エラーが発生しました

ストレージノードとクラウドストレージプールに使用される外部 S3 エンドポイントとの間に、透過性のないストレージ プロキシ サーバを設定している場合、このエラーが発生する可能性があります。このエラーは、外部プロキシ サーバがクラウドストレージプールのエンドポイントに到達できない場合に発生します。たとえば、DNS サーバがホスト名を解決できない場合や、外部ネットワークに問題が発生している場合があります。

問題を解決するには、以下の手順を1つ以上試してください。

* クラウドストレージプールの設定を確認してください（*ILM* > *ストレージプール*）。
* ストレージ プロキシ サーバのネットワーク構成を確認してください。




[[error-x-509-certificate-is-out-of-validity-period]]
== エラー：X.509証明書の有効期限が切れています

クラウドストレージプールを削除しようとした際に、このエラーが発生する場合があります。このエラーは、認証に X.509 証明書が必要で、正しい外部クラウドストレージプールが検証され、かつクラウドストレージプール構成が削除される前に外部プールが空であることを確認する必要がある場合に発生します。

問題を解決するには、以下の手順を試してください。

* クラウドストレージプールへの認証用に設定されている証明書を更新してください。
* このクラウドストレージプールに関する証明書の有効期限切れ警告がすべて解決されていることを確認してください。
