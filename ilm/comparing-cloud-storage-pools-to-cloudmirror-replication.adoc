= StorageGRID におけるクラウドストレージプールと CloudMirror レプリケーション
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
クラウドストレージプールの使用を開始するにあたり、クラウドストレージプールと StorageGRID CloudMirror レプリケーションサービスの類似点と相違点を理解しておくと役立つ場合があります。

[cols="1a,3a,3a"]
|===
|  | クラウド ストレージ プール | CloudMirrorレプリケーションサービス 


 a| 
主な目的は何ですか？
 a| 
アーカイブ対象として機能します。クラウドストレージプール内のオブジェクトコピーは、オブジェクトの唯一のコピーである場合もあれば、追加のコピーである場合もあります。つまり、2つのコピーをオンサイトに保管する代わりに、1つのコピーを StorageGRID 内に保管し、もう1つのコピーをクラウドストレージプールに送信することができます。
 a| 
テナントが StorageGRID のバケット（ソース）から外部の S3 バケット（宛先）にオブジェクトを自動的にレプリケートできるようにします。独立した S3 インフラ内に、オブジェクトの独立したコピーを作成します。



 a| 
どのように設定されているのですか？
 a| 
ストレージプールと同様の方法で、Grid ManagerまたはGrid Management APIを使用して定義します。ILMルールにおける配置場所として選択できます。ストレージプールはストレージノードのグループで構成されますが、クラウドストレージプールはリモートのS3またはAzureエンドポイント（IPアドレス、認証情報など）を使用して定義されます。
 a| 
テナントユーザーは、Tenant Manager または S3 API を使用して CloudMirror エンドポイント（IP アドレス、認証情報など）を定義することでlink:../tenant/configuring-cloudmirror-replication.html["CloudMirror レプリケーションを設定します"]。CloudMirror エンドポイントが設定されると、そのテナントアカウントが所有するすべてのバケットを CloudMirror エンドポイントに向けるように設定できます。



 a| 
誰が設定を担当するのですか？
 a| 
通常、グリッド管理者
 a| 
通常、テナントユーザー



 a| 
宛先は何ですか？
 a| 
* 互換性のあるS3インフラストラクチャ（Amazon S3を含む）
* Azure Blob Archive 層
* Google Cloud Platform（GCP）

 a| 
* 互換性のあるS3インフラストラクチャ（Amazon S3を含む）
* Google Cloud Platform（GCP）




 a| 
オブジェクトが移動先に移動される原因は何ですか？
 a| 
有効なILMポリシーに、1つ以上のILMルールが含まれている。ILMルールは、StorageGRIDがクラウドストレージプールに移動するオブジェクトと、オブジェクトが移動されるタイミングを定義します。
 a| 
CloudMirror エンドポイントが設定されたソースバケットに新しいオブジェクトを取り込む操作。バケットに CloudMirror エンドポイントが設定される前にソースバケットに存在していたオブジェクトは、変更されない限りレプリケートされません。



 a| 
オブジェクトはどのように取得されますか？
 a| 
アプリケーションは、クラウドストレージプールに移動されたオブジェクトを取得するために、StorageGRID にリクエストを送信する必要があります。オブジェクトのコピーがアーカイブストレージにのみ移行されている場合、StorageGRID はオブジェクトを復元して取得できるようにするプロセスを管理します。
 a| 
宛先バケット内のミラーコピーは独立したコピーであるため、アプリケーションは StorageGRID または S3 宛先のいずれかにリクエストを送信することでオブジェクトを取得できます。たとえば、CloudMirror レプリケーションを使用してオブジェクトをパートナー組織にミラーリングするとします。パートナーは、独自のアプリケーションを使用して、S3 宛先からオブジェクトを直接読み取ったり更新したりできます。StorageGRID を使用する必要はありません。



 a| 
宛先から直接読み込むことはできますか？
 a| 
いいえ。クラウドストレージプールに移動されたオブジェクトは、StorageGRID によって管理されます。読み取りリクエストは StorageGRID に送信する必要があります（StorageGRID がクラウドストレージプールからのデータ取得を担当します）。
 a| 
はい、ミラーコピーは独立したコピーであるためです。



 a| 
ソースからオブジェクトが削除された場合、どうなりますか？
 a| 
当該オブジェクトはクラウドストレージプールからも削除されます。
 a| 
削除操作は複製されません。削除されたオブジェクトは StorageGRID バケットには存在しなくなりますが、宛先バケットには引き続き存在します。同様に、宛先バケット内のオブジェクトは、ソースに影響を与えることなく削除できます。



 a| 
災害後にオブジェクトにアクセスするにはどうすればよいですか（StorageGRID システムが動作していない場合）？
 a| 
障害が発生した StorageGRID ノードを復旧する必要があります。このプロセス中に、レプリケートされたオブジェクトのコピーが、クラウドストレージプール内のコピーを使用して復元される場合があります。
 a| 
CloudMirrorデスティネーション内のオブジェクトコピーは StorageGRID から独立しているため、StorageGRID ノードがリカバリされる前に直接アクセスできます。

|===
