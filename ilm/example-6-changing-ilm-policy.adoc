= ILMポリシーの変更がStorageGRIDパフォーマンスに及ぼす影響
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
データ保護に関する方針を変更する必要がある場合、または新しいサイトを追加する場合は、新しいILMポリシーを作成して有効化できます。

ポリシーを変更する前に、ILM配置の変更が StorageGRID システムの全体的なパフォーマンスに一時的にどのような影響を与えるかを理解しておく必要があります。

この例では、拡張によって新しい StorageGRID サイトが追加されたため、新しいサイトにデータを保存するための新しいアクティブな ILM ポリシーを実装する必要があります。新しいアクティブなポリシーを実装するには、まず link:creating-ilm-policy.html["ポリシーを作成する"]。その後、link:../ilm/creating-ilm-policy.html#simulate-ilm-policy["シミュレーション"] してから、新しいポリシーを link:../ilm/creating-ilm-policy.html#activate-ilm-policy["アクティブ化"] する必要があります。


CAUTION: 以下のILMルールおよびポリシーは、あくまで例です。ILMルールを設定する方法は数多くあります。新しいポリシーを有効にする前に、シミュレーションを実行して、意図したとおりに機能し、コンテンツの損失を防ぐことができることを確認してください。



[[how-changing-an-ilm-policy-affects-performance]]
== ILMポリシーの変更がパフォーマンスに与える影響

新しい ILM ポリシーを有効化すると、StorageGRID システムのパフォーマンスが一時的に影響を受ける可能性があります。これは特に、新しいポリシーの配置指示によって、既存の多くのオブジェクトを新しい場所に移動する必要がある場合に発生します。

新しい ILM ポリシーを有効にすると、StorageGRID は既存のオブジェクトと新たに取り込まれたオブジェクトを含む、すべてのオブジェクトの管理に使用されます。新しい ILM ポリシーを有効にする前に、既存のレプリケートされたオブジェクトおよびイレイジャー コーディングされたオブジェクトの配置変更を確認してください。既存オブジェクトの場所を変更すると、新しい配置が評価および実装される際に、一時的なリソースの問題が発生する可能性があります。

新しい ILM ポリシーが既存のレプリケートオブジェクトおよびイレイジャー コーディングオブジェクトの配置に影響を与えないようにするには、link:create-ilm-rule-enter-details.html#use-advanced-filters-in-ilm-rules["取り込み時間フィルターを使用してILMルールを作成する"]。例えば、*取り込み時間が _<date and time>_ 以降_である_*場合、新しいルールは指定された日時以降に取り込まれたオブジェクトにのみ適用されます。

StorageGRID のパフォーマンスに一時的な影響を与える可能性のある ILM ポリシー変更の種類には、次のものがあります：

* 既存のイレイジャー コーディングされたオブジェクトに、異なるイレイジャー コーディング プロファイルを適用する。
+

NOTE: StorageGRID は、各イレイジャー コーディング プロファイルを固有のものとみなし、新しいプロファイルが使用される際にはイレイジャー コーディング フラグメントを再利用しません。

* 既存オブジェクトに必要なコピーの種類を変更する。たとえば、レプリケートされたオブジェクトの大部分をイレイジャー コーディング オブジェクトに変換する。
* 既存オブジェクトのコピーを全く別の場所に移動する。例えば、多数のオブジェクトを Cloud Storage Pool との間で移動したり、リモートサイトとの間で移動したりする。

[[ilm-policy-for-example-6-data-protection-at-three-sites]]
== ILMポリシー例6：3つの拠点におけるデータ保護

この例では、ILMポリシーが3サイト構成の StorageGRID システム向けの新しいポリシーに置き換えられています。

新しいサイトを追加するための拡張を実行した後、グリッド管理者は2つの新しいストレージプールを作成しました。1つはサイト3用のストレージプール、もう1つは3つのサイトすべてを含むストレージプールです（デフォルトの「すべてのストレージノード」ストレージプールとは異なります）。その後、管理者は3つのサイトすべてのデータを保護するように設計された、2つの新しいILMルールと1つの新しいILMポリシーを作成しました。

この新しいILMポリシーが有効になると、テナントAに属するオブジェクトは3つのサイトで2+1イレイジャー コーディングによって保護され、他のテナントに属するオブジェクト（およびテナントAに属するより小さなオブジェクト）は、3コピーレプリケーションを使用して3つのサイト間で保護されます。

[[activating-the-ilm-policy-for-example-6]]
== 例6のILMポリシーのアクティブ化

新しいILMポリシーを有効化すると、新規または更新されたルール内の配置指示に基づいて、既存のオブジェクトが新しい場所に移動されたり、既存のオブジェクトの新しいコピーが作成されたりする場合があります。


CAUTION: ILMポリシーに誤りがあると、回復不能なデータ損失を引き起こす可能性があります。ポリシーを有効化する前に、慎重に内容を確認し、シミュレーションを実行して、意図どおりに機能することを確認してください。


CAUTION: 新しい ILM ポリシーを有効にすると、StorageGRID は既存のオブジェクトと新たに取り込まれたオブジェクトを含む、すべてのオブジェクトの管理に使用されます。新しい ILM ポリシーを有効にする前に、既存のレプリケートされたオブジェクトおよびイレイジャー コーディングされたオブジェクトの配置変更を確認してください。既存オブジェクトの場所を変更すると、新しい配置が評価および実装される際に、一時的なリソースの問題が発生する可能性があります。



[[what-happens-when-erasure-coding-instructions-change]]
=== イレイジャー コーディングの手順が変更された場合の動作

この例で現在有効なILMポリシーでは、テナントAに属するオブジェクトはサイト1で2+1イレイジャー コーディングを使用して保護されています。新しいILMポリシーでは、テナントAに属するオブジェクトはサイト1、2、3で2+1イレイジャー コーディングを使用して保護されます。

新しいILMポリシーが有効化されると、以下のILM操作が実行されます：

* テナント A によって取り込まれた新しいオブジェクトは、2 つのデータフラグメントに分割され、1 つのパリティフラグメントが追加されます。そして、3 つのフラグメントはそれぞれ異なるサイトに保存されます。
* テナントAが所有する既存のオブジェクトは、進行中のILMスキャンプロセス中に再評価されます。ILMの配置指示では新しいイレイジャー コーディングプロファイルが使用されるため、まったく新しいイレイジャー コーディングされたフラグメントが作成され、3つのサイトに配布されます。
+

NOTE: サイト1に存在する既存の2+1個のフラグメントは再利用されません。StorageGRIDは、各イレイジャー コーディングプロファイルを固有のものとみなし、新しいプロファイルが使用される際にはイレイジャー コーディングのフラグメントは再利用されません。





[[what-happens-when-replication-instructions-change]]
=== 複製手順が変更されるとどうなるか

この例で現在有効なILMポリシーでは、他のテナントに属するオブジェクトは、サイト1とサイト2のストレージプールに2つのレプリケートコピーを使用して保護されています。新しいILMポリシーでは、他のテナントに属するオブジェクトは、サイト1、2、3のストレージプールに3つのレプリケートコピーを使用して保護されます。

新しいILMポリシーが有効化されると、以下のILM操作が実行されます：

* テナントA以外のテナントが新しいオブジェクトを取り込むと、StorageGRID は3つのコピーを作成し、各サイトに1つずつ保存します。
* これらの他のテナントに属する既存のオブジェクトは、進行中のILMスキャンプロセス中に再評価されます。サイト1とサイト2の既存のオブジェクトコピーは、新しいILMルールのレプリケーション要件を引き続き満たしているため、StorageGRIDはサイト3用にオブジェクトの新しいコピーを1つ作成するだけで済みます。




[[performance-impact-of-activating-this-policy]]
=== このポリシーを有効化した場合のパフォーマンスへの影響

この例では ILM ポリシーがアクティブ化されると、この StorageGRID システムの全体的なパフォーマンスに一時的な影響が生じます。テナント A の既存オブジェクト用の新しいイレイジャー コーディング フラグメントを作成するため、および他のテナントの既存オブジェクト用の新しいレプリケートコピーをサイト 3 に作成するためには、通常よりも多くのグリッドリソースが必要になります。

ILMポリシーの変更に伴い、クライアントの読み取りおよび書き込みリクエストにおいて、一時的に通常よりも高いレイテンシが発生する可能性があります。配置指示がグリッド全体に完全に実装されると、レイテンシは通常レベルに戻ります。

新しいILMポリシーを有効化する際にリソースの問題を回避するには、既存の多数のオブジェクトの場所を変更する可能性のあるルールで、取り込み時間の詳細フィルターを使用できます。既存のオブジェクトが不必要に移動されないように、取り込み時間を新しいポリシーが有効になるおおよその時刻以上に設定してください。


NOTE: ILMポリシーの変更後にオブジェクトの処理速度を遅くしたり速くしたりする必要がある場合は、テクニカルサポートにお問い合わせください。
