= StorageGRID の厳格な取り込み動作に関する ILM ルールとポリシー
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ロケーション フィルタとルールの厳密な取り込み動作を使用して、特定のデータセンターの場所にオブジェクトが保存されないようにすることができます。

この例では、パリに拠点を置くテナントが、規制上の懸念から、一部のオブジェクトをEU域外に保管することを望んでいません。他のテナントアカウントのすべてのオブジェクトを含むその他のオブジェクトは、パリのデータセンターまたは米国のデータセンターのいずれかに保存できます。


CAUTION: 以下のILMルールおよびポリシーは、あくまで例です。ILMルールを設定する方法は数多くあります。新しいポリシーを有効にする前に、シミュレーションを実行して、意図したとおりに機能し、コンテンツの損失を防ぐことができることを確認してください。

[[ilm-rule-1-for-example-5-strict-ingest-to-guarantee-paris-data-center]]
== ILMルール1（例5）：パリのデータセンターを保証するための厳格な取り込み

この ILM ルールの例では、厳密な取り込み動作を使用して、パリを拠点とするテナントによってリージョンが eu-west-3 リージョン（パリ）に設定された S3 バケットに保存されたオブジェクトが、米国のデータセンターに保存されないことを保証します。

このルールは、パリのテナントに属し、S3バケットリージョンが eu-west-3 （パリ）に設定されているオブジェクトに適用されます。

[[ilm-rule-2-for-example-5-balanced-ingest-for-other-objects]]
== ILM ルール 2（例 5）：その他のオブジェクトのバランスの取れた取り込み

このILMルールの例では、バランスのとれた取り込み動作を使用して、最初のルールに一致しないオブジェクトに対して最適なILM効率を実現します。このルールに一致するすべてのオブジェクトのコピーが2つ保存されます。1つは米国のデータセンターに、もう1つはパリのデータセンターに保存されます。ルールをすぐに満たすことができない場合は、暫定的なコピーが利用可能な場所に保存されます。

このルールは、どのテナントおよびどのリージョンに属するオブジェクトにも適用されます。

[[ilm-policy-for-example-5-combining-ingest-behaviors]]
== ILMポリシーの例5：取り込み動作の組み合わせ

このILMポリシーの例には、取り込み動作が異なる2つのルールが含まれています。

2つの異なる取り込み動作を使用するILMポリシーには、次のようなILMルールが含まれる場合があります。

* パリのテナントに属し、S3バケットのリージョンがeu-west-3（パリ）に設定されているオブジェクトは、パリのデータセンターにのみ保存します。パリのデータセンターが利用できない場合は、データ取り込みに失敗します。
* その他のすべてのオブジェクト（パリのテナントに属するがバケットリージョンが異なるオブジェクトを含む）は、米国のデータセンターとパリのデータセンターの両方に保存します。配置指示を満たせない場合は、利用可能な場所に仮コピーを作成します。


ポリシーの例をシミュレートすると、テストオブジェクトは次のように評価されます。

* パリのテナントに属し、S3バケットのリージョンがeu-west-3に設定されているオブジェクトは、最初のルールに一致し、パリのデータセンターに保存されます。最初のルールでは Strict の取り込みを使用しているため、これらのオブジェクトは米国のデータセンターには保存されません。パリのデータセンターにあるストレージノードが利用できない場合、取り込みは失敗します。
* その他のすべてのオブジェクトは、2 番目のルールに一致します。これには、パリのテナントに属し、S3 バケットのリージョンが eu-west-3 に設定されていないオブジェクトも含まれます。各オブジェクトのコピーは、各データセンターに 1 つずつ保存されます。ただし、2 番目のルールでは Balanced 取り込みを使用しているため、1 つのデータセンターが利用できない場合、2 つの暫定コピーが利用可能な任意の場所に保存されます。
