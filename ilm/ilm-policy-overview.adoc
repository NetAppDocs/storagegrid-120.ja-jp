= StorageGRIDのILMポリシーについて学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
情報ライフサイクル管理（ILM）ポリシーは、StorageGRID システムが長期にわたってオブジェクトデータを管理する方法を決定する、ILM ルールの順序付きセットです。


CAUTION: 設定が誤っているILMポリシーは、回復不能なデータ損失を引き起こす可能性があります。ILMポリシーを有効化する前に、ILMポリシーとそのILMルールを注意深く確認し、その後ILMポリシーのシミュレーションを行ってください。ILMポリシーが意図どおりに機能することを必ず確認してください。



[[default-ilm-policy]]
== デフォルトのILMポリシー

StorageGRID をインストールしてサイトを追加すると、以下のようにデフォルトの ILM ポリシーが自動的に作成されます。

* グリッドにサイトが1つしかない場合、デフォルトポリシーには、そのサイトにある各オブジェクトのコピーを2つ複製するデフォルトルールが含まれています。
* グリッドに複数のサイトが含まれている場合、デフォルトのルールでは、各サイトに各オブジェクトのコピーが1つずつ複製されます。


デフォルトのポリシーがストレージ要件を満たさない場合は、独自のルールとポリシーを作成できます。link:what-ilm-rule-is.html["ILMルールを作成する"]およびlink:creating-ilm-policy.html["ILMポリシーを作成する"]を参照してください。



[[one-or-many-active-ilm-policies]]
== 有効なILMポリシーは1つですか、それとも複数ありますか？

同時に有効なILMポリシーは1つ以上設定できます。



[[one-policy]]
=== 1つのポリシー

グリッドがテナント固有およびバケット固有のルールが少ないシンプルなデータ保護スキームを使用する場合は、単一のアクティブなILMポリシーを使用してください。ILMルールには、異なるバケットやテナントを管理するためのフィルターを含めることができます。

image:ilm-policies-single.png["単一 ILM ポリシー図"]

ポリシーが1つしかない場合にテナントの要件が変更されると、新しいILMポリシーを作成するか、既存のポリシーを複製して変更を適用し、シミュレーションを実行してから、新しいILMポリシーをアクティブ化する必要があります。ILMポリシーの変更は、オブジェクトの移動に数日かかる可能性があり、システム遅延を引き起こす可能性があります。



[[multiple-policies]]
=== 複数のポリシー

テナントにさまざまなサービス品質の選択肢を提供するために、複数のアクティブなポリシーを同時に設定することができます。各ポリシーは、特定のテナント、S3 バケット、およびオブジェクトを管理できます。特定のテナントまたはオブジェクトのセットに対してポリシーを適用または変更しても、他のテナントおよびオブジェクトに適用されているポリシーには影響しません。

ILMポリシータグ:: テナントがバケットごとに複数のデータ保護ポリシーを簡単に切り替えられるようにするには、_ILMポリシータグ_を使用して複数のILMポリシーを使用します。各ILMポリシーにタグを割り当て、テナントはバケットにタグを付けることで、そのバケットにポリシーを適用します。ILMポリシータグはS3バケットにのみ設定できます。
+
--
例えば、ゴールド、シルバー、ブロンズという名前のタグが3つあるとします。各タグに対して、そのポリシーがオブジェクトを保存する期間と場所に基づいて、ILMポリシーを割り当てることができます。テナントは、自分のバケットにタグを付けることで、使用するポリシーを選択できます。ゴールドタグが付いたバケットは、ゴールドポリシーによって管理され、ゴールドレベルのデータ保護とパフォーマンスが提供されます。

--



NOTE: グリッドに対してlink:../ilm/creating-ilm-policy.html#activate-ilm-policy["最大10個のポリシータグを作成します"]できます。

デフォルトのILMポリシータグ:: StorageGRID のインストール時に、デフォルトの ILM ポリシータグが自動的に作成されます。すべてのグリッドには、Default タグに割り当てられたアクティブなポリシーが 1 つ必要です。デフォルトポリシーは、タグ付けされていないすべての S3 バケットに適用されます。


image:ilm-policies-tags-conceptual.png["複数のILMポリシーの図"]



[[how-does-an-ilm-policy-evaluate-objects]]
== ILMポリシーは、どのようにオブジェクトを評価するのでしょうか？

アクティブなILMポリシーは、オブジェクトの配置、期間、およびデータ保護を制御します。

クライアントがオブジェクトを StorageGRID に保存すると、オブジェクトはポリシー内の順序付けられた ILM ルールセットに対して、以下のように評価されます。

. ポリシー内の最初のルールのフィルタがオブジェクトに一致する場合、そのオブジェクトはそのルールの取り込み動作に従って取り込まれ、そのルールの配置指示に従って保存されます。
. 最初のルールのフィルタがオブジェクトと一致しない場合、一致するルールが見つかるまで、そのオブジェクトはポリシー内の後続の各ルールに対して評価されます。
. オブジェクトに一致するルールがない場合、ポリシー内のデフォルトルールの取り込み動作と配置手順が適用されます。デフォルトルールは、ポリシーの最後のルールです。デフォルトルールは、すべてのテナント、すべての S3 バケット、およびすべてのオブジェクトバージョンに適用される必要があり、高度なフィルターは使用できません。




[[example-ilm-policy]]
== ILMポリシーの例

例えば、ILMポリシーには、以下の内容を指定する3つのILMルールが含まれる場合があります。

* *ルール1：テナントA向けの複製コピー*
+
** テナントAに属するすべてのオブジェクトを一致させます。
** これらのオブジェクトを、3か所のサイトにレプリケートされた3つのコピーとして保存します。
** 他のテナントに属するオブジェクトはルール 1 に一致しないため、ルール 2 に基づいて評価されます。


* *ルール2：1 MBを超えるオブジェクトに対するイレイジャー コーディング*
+
** 他のテナントのすべてのオブジェクトを照合しますが、サイズが1 MBを超えるものに限ります。これらの大型オブジェクトは、3つのサイトで6+3イレイジャー コーディングを使用して保管されます。
** 1 MB以下のオブジェクトには一致しないため、これらのオブジェクトはルール3に基づいて評価されます。


* *ルール3：2コピー、2データセンター*（デフォルト）
+
** これはポリシーにおける最後のデフォルトルールです。フィルターは使用しません。
** ルール1またはルール2に一致しないすべてのオブジェクト（テナントAに属さず、サイズが1 MB以下のオブジェクト）の複製コピーを2つ作成します。




image:ilm_policy_and_rules.png["ILM ポリシーとルール"]



[[what-are-active-and-inactive-policies]]
== アクティブポリシーと非アクティブポリシーとは何ですか？

StorageGRID システムには、少なくとも1つの有効な ILM ポリシーが必要です。複数の ILM ポリシーをアクティブにする場合は、ILM ポリシータグを作成し、各タグにポリシーを割り当てます。テナントはその後、S3 バケットにタグを適用します。デフォルトポリシーは、ポリシータグが割り当てられていないバケット内のすべてのオブジェクトに適用されます。

ILMポリシーを初めて作成する際には、1つ以上のILMルールを選択し、特定の順序で配置します。ポリシーの動作を確認するためにシミュレーションを行った後、そのポリシーを有効化します。

ILM ポリシーを 1 つ有効化すると、StorageGRID はこのポリシーを使用して、既存のオブジェクトと新たに取り込まれたオブジェクトを含む、すべてのオブジェクトを管理します。新しいポリシーの ILM ルールが実装されると、既存のオブジェクトが新しい場所に移動される場合があります。

複数のILMポリシーを同時に有効化し、テナントがS3バケットにポリシータグを適用すると、各バケット内のオブジェクトは、そのタグに割り当てられたポリシーに従って管理されます。

StorageGRID システムは、有効化または無効化されたポリシーの履歴を追跡します。



[[considerations-for-creating-an-ilm-policy]]
== ILMポリシーを作成する際の考慮事項

* テストシステムでは、システムが提供するポリシーである「ベースライン2コピーポリシー」のみを使用してください。StorageGRID 11.6以前では、このポリシーの「2つのコピーを作成する」ルールは、すべてのサイトを含む「すべてのストレージノード」ストレージプールを使用します。StorageGRIDシステムに複数のサイトがある場合、同じサイトにオブジェクトのコピーが2つ配置される可能性があります。
+

NOTE: All Storage Nodes ストレージプールは、StorageGRID 11.6 以前のインストール時に自動的に作成されます。StorageGRID の新しいバージョンにアップグレードした場合でも、All Storage Nodes プールは引き続き存在します。StorageGRID 11.7 以降を新規インストールとしてインストールする場合、All Storage Nodes プールは作成されません。

* 新しいポリシーを設計する際には、グリッドに取り込まれる可能性のあるあらゆる種類のオブジェクトを考慮してください。ポリシーには、これらのオブジェクトを必要に応じて照合および配置するためのルールが含まれていることを確認してください。
* ILM ポリシーはできる限りシンプルに保ってください。これにより、StorageGRID システムに対して時間の経過とともに変更が加えられた際に、オブジェクトデータが意図したとおりに保護されないという潜在的に危険な状況を回避できます。
* ポリシー内のルールが正しい順序で設定されていることを確認してください。ポリシーが有効になると、新規および既存のオブジェクトは、リストに記載されている順序で上から順にルールによって評価されます。たとえば、ポリシー内の最初のルールがオブジェクトに一致した場合、そのオブジェクトは他のどのルールによっても評価されません。
* すべての ILM ポリシーの最後のルールはデフォルトの ILM ルールであり、フィルタを使用することはできません。オブジェクトが他のルールに一致しなかった場合、デフォルトルールによってそのオブジェクトの配置場所と保持期間が制御されます。
* 新しいポリシーを有効にする前に、そのポリシーが既存のオブジェクトの配置にどのような変更を加えるかを確認してください。既存オブジェクトの場所を変更すると、新しい配置が評価および実装される際に、一時的なリソースの問題が発生する可能性があります。
