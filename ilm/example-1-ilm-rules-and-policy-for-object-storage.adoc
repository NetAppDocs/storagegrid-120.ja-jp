[role="lead"]
オブジェクトの保護および保持に関する要件を満たすILMポリシーを定義する際には、以下の例となるルールとポリシーを参考にしてください。


CAUTION: 以下のILMルールおよびポリシーは、あくまで例です。ILMルールを設定する方法は数多くあります。新しいポリシーを有効にする前に、シミュレーションを実行して、意図したとおりに機能し、コンテンツの損失を防ぐことができることを確認してください。



[[ilm-rule-1-for-example-1-copy-object-data-to-two-sites]]
== ILMルール1の例1：オブジェクトデータを2つのサイトにコピーする

このILMルールの例では、オブジェクトデータを2つのサイトのストレージプールにコピーします。

[cols="1a,2a"]
|===
| ルール定義 | 例の値 


 a| 
単一サイトのストレージプール
 a| 
それぞれ異なるサイトを含む2つのストレージプールがあり、Site 1とSite 2という名前が付けられています。



 a| 
ルール名
 a| 
2つのコピー、2つのサイト



 a| 
基準時間
 a| 
取り込み時間



 a| 
配置
 a| 
0日目から永久に、複製コピーを1部サイト1に、複製コピーを1部サイト2に保管してください。

|===
保持図のルール分析セクションには、次のように記載されています。

* StorageGRID のサイト損失保護は、このルールの有効期間中に適用されます。
* このルールによって処理されたオブジェクトは、ILMによって削除されません。


image:ilm_rule_two_copies_two_data_centers.png["ILMルール1の例1：オブジェクトデータを2つのサイトにコピーする"]



[[ilm-rule-2-for-example-1-erasure-coding-profile-with-bucket-matching]]
== ILM ルール 2（例 1）：バケットマッチング付きイレイジャー コーディングプロファイル

このILMルールの例では、イレイジャー コーディングプロファイルとS3バケットを使用して、オブジェクトの保存場所と保存期間を決定します。

[cols="1a,2a"]
|===
| ルール定義 | 例の値 


 a| 
複数のサイトを持つストレージプール
 a| 
* 3つのサイト（サイト1、2、3）にまたがる1つのストレージプール
* 6+3 イレイジャー コーディング方式を使用する




 a| 
ルール名
 a| 
S3バケット finance-records



 a| 
基準時間
 a| 
取り込み時間



 a| 
配置
 a| 
finance-records という名前の S3 バケット内のオブジェクトについては、イレイジャー コーディング プロファイルで指定されたプール内に、イレイジャー コーディングされたコピーを 1 つ作成します。このコピーは永久に保管します。

|===
image:ilm_rule_ec_for_s3_bucket_finance_records.png["ILMルール2（例1）：バケットマッチングを使用したイレイジャー コーディングプロファイル"]



[[ilm-policy-for-example-1]]
== ILMポリシーの例1

実際には、ほとんどの ILM ポリシーはシンプルですが、StorageGRID システムを使用すると、高度で複雑な ILM ポリシーを設計することができます。

複数拠点グリッド向けの一般的なILMポリシーには、次のようなILMルールが含まれる場合があります：

* 取り込み時に、 `finance-records` という名前の S3 バケットに属するすべてのオブジェクトを、3 つのサイトを含むストレージプールに保存します。6+3 イレイジャー コーディングを使用します。
* オブジェクトが最初の ILM ルールに一致しない場合は、ポリシーのデフォルトの ILM ルールである「Two Copies Two Data Centers」を使用して、そのオブジェクトのコピーを 1 つサイト 1 に、もう 1 つをサイト 2 に保存します。
