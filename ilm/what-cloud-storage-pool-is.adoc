= StorageGRID のクラウドストレージプールについて学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
クラウドストレージプールを使用すると、ILM を使用してオブジェクトデータを StorageGRID システムの外部に移動できます。たとえば、アクセス頻度の低いオブジェクトを、Amazon S3 Glacier、S3 Glacier Deep Archive、Google Cloud、Microsoft Azure Blob ストレージのアーカイブアクセス層などの低コストのクラウドストレージに移動することができます。または、災害復旧を強化するために StorageGRID オブジェクトのクラウドバックアップを保持することもできます。

ILM の観点から見ると、クラウドストレージプールはストレージプールに似ています。オブジェクトをどちらの場所にも保存するには、ILM ルールの配置指示を作成する際にプールを選択します。ただし、ストレージプールは StorageGRID システム内のストレージノードで構成されるのに対し、クラウドストレージプールは外部バケット（S3）またはコンテナ（Azure Blob ストレージ）で構成されます。

この表では、ストレージプールと Cloud Storage Pool を比較し、概要レベルでの類似点と相違点を示します。

[cols="1a,2a,5a"]
|===
|  | ストレージ プール | クラウド ストレージ プール 


 a| 
それはどのように作られるのですか？
 a| 
Grid Manager の *ILM* > *ストレージ プール* オプションを使用します。
 a| 
Grid Manager の *ILM* > *ストレージ プール* > *クラウド ストレージ プール* オプションを使用します。

クラウドストレージプールを作成する前に、外部バケットまたはコンテナを設定する必要があります。



 a| 
いくつのプールを作成できますか？
 a| 
無制限。
 a| 
最大10個まで。



 a| 
オブジェクトはどこに保存されますか？
 a| 
StorageGRID 内の 1 つ以上のストレージ ノード上。
 a| 
StorageGRID システムの外部にある Amazon S3 バケット、Azure Blob ストレージ コンテナ、または Google Cloud。

クラウドストレージプールが Amazon S3 バケットの場合：

* バケットのライフサイクルをオプションで構成して、Amazon S3 Glacier や S3 Glacier Deep Archive などの低コストな長期保存用のストレージにオブジェクトを移行できます。外部ストレージシステムは、Glacier ストレージクラスと S3 RestoreObject API をサポートしている必要があります。
* AWS シークレットリージョンをサポートする AWS 商用クラウドサービス (C2S) で使用するクラウドストレージプールを作成できます。


クラウドストレージプールが Azure Blob ストレージコンテナである場合、StorageGRID はオブジェクトをアーカイブ階層に移行します。

*注:* 一般的に、クラウド ストレージ プールに使用されるコンテナーに対して、Azure Blob ストレージのライフサイクル管理を構成しないでください。RestoreObject クラウド ストレージ プール内のオブジェクトに対する操作は、設定されたライフサイクルによって影響を受ける可能性があります。



 a| 
オブジェクトの配置を制御するものは何ですか？
 a| 
有効なILMポリシーに含まれるILMルール。
 a| 
有効なILMポリシーに含まれるILMルール。



 a| 
どのようなデータ保護方法が用いられていますか？
 a| 
複製またはイレイジャー コーディング。
 a| 
レプリケーション。



 a| 
各オブジェクトはいくつまで複製できますか？
 a| 
複数。
 a| 
クラウド ストレージ プールに 1 つのコピー、およびオプションで StorageGRID に 1 つ以上のコピー。

*注:* 同時に複数のクラウドストレージプールにオブジェクトを保存することはできません。



 a| 
利点は何ですか？
 a| 
必要なオブジェクトはいつでもすぐにアクセスできます。
 a| 
低コストのストレージ。

*注記*：FabricPool データはクラウドストレージプールに階層化できません。

|===
