= S3バケットライフサイクルとILMポリシーがStorageGRIDでどのように相互作用するか
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ライフサイクル構成に応じて、オブジェクトはS3バケットのライフサイクルまたはILMポリシーのいずれかの保持ポリシーに従います。



[[example-of-bucket-lifecycle-taking-priority-over-ilm-policy]]
== バケットのライフサイクルがILMポリシーよりも優先される例

ILM ポリシー::
+
--
* 非現在時刻参照に基づくルール：0日目に、X部を20日間保管する
* 取り込み時間基準に基づくルール（デフォルト）：0日目に、X個のコピーを50日間保持する


--
バケットのライフサイクル:: `"Filter": {"Prefix": "docs/"}, "Expiration": {"Days": 100}, "NoncurrentVersionExpiration": {"NoncurrentDays": 5}`
結果::
+
--
* 「docs/text」という名前のオブジェクトが取り込まれます。これは、バケットライフサイクルフィルターの「docs/」プレフィックスに一致します。
+
** 100日後には削除マーカーが作成され、「docs/text」は非現行ファイルになります。
** 5日後、つまり取り込みから合計105日経過すると、「docs/text」は削除されます。
** 95日後、つまりデータ取り込みから合計200日、削除マーカー作成から100日経過すると、期限切れの削除マーカーが削除されます。


* 「video/movie」という名前のオブジェクトが取り込まれます。フィルターに一致せず、ILM 保持ポリシーを使用します。
+
** 50日後に削除マーカーが作成され、「video/movie」は非カレントになります。
** 取り込みから20日後、合計70日経過すると、「ビデオ/ムービー」は削除されます。
** 30日後、つまりデータ取り込みから合計100日、削除マーカー作成から50日経過すると、期限切れの削除マーカーが削除されます。




--




[[example-of-bucket-lifecycle-implicitly-keeping-forever]]
== バケットのライフサイクルの例（暗黙的に永久保持）

ILM ポリシー::
+
--
* 非現在時刻参照に基づくルール：0日目に、X部を20日間保管する
* 取り込み時間基準に基づくルール（デフォルト）：0日目に、X個のコピーを50日間保持する


--
バケットのライフサイクル:: `"Filter": {"Prefix": "docs/"}, "Expiration": {"ExpiredObjectDeleteMarker": true}`
結果::
+
--
* 「docs/text」という名前のオブジェクトが取り込まれます。これは、バケットライフサイクルフィルターの「docs/」プレフィックスに一致します。
+
The `Expiration`このアクションは期限切れの削除マーカーにのみ適用され、それ以外のすべて（「docs/」で始まるもの）は永久に保持されることを意味します。

+
「docs/」で始まる削除マーカーは、有効期限が切れると削除されます。

* 「video/movie」という名前のオブジェクトが取り込まれます。フィルターに一致せず、ILM 保持ポリシーを使用します。
+
** 50日後に削除マーカーが作成され、「video/movie」は非カレントになります。
** 取り込みから20日後、合計70日経過すると、「ビデオ/ムービー」は削除されます。
** 30日後、つまりデータ取り込みから合計100日、削除マーカー作成から50日経過すると、期限切れの削除マーカーが削除されます。




--




[[example-of-using-bucket-lifecycle-to-duplicate-ilm-and-clean-up-expired-delete-markers]]
== バケットライフサイクルを使用してILMを複製し、期限切れの削除マーカーをクリーンアップする例

ILM ポリシー::
+
--
* 非現在時刻参照に基づくルール：0日目に、X部を20日間保管する
* 取り込み時間基準に基づくルール（デフォルト）：0日目に、Xコピーを永久に保持する


--
バケットのライフサイクル:: `"Filter": {}, "Expiration": {"ExpiredObjectDeleteMarker": true}, "NoncurrentVersionExpiration": {"NoncurrentDays": 20}`
結果::
+
--
* ILMポリシーはバケットのライフサイクル内で複製されます。
+
** ILMポリシーの「永久ルール」は、オブジェクトを手動で削除し、20日後に旧バージョンをクリーンアップするために設計されています。したがって、取り込み時ルールは、期限切れの削除マーカーを永久に保持します。
** バケットライフサイクルは、ILMポリシーの動作を複製しながら、 `"ExpiredObjectDeleteMarker": true`を追加します。これにより、有効期限が切れた削除マーカーが削除されます。


* オブジェクトが取り込まれます。フィルターなしとは、バケットのライフサイクルがすべてのオブジェクトに適用され、ILM の保持設定を上書きすることを意味します。
+
** テナントがオブジェクト削除要求を発行すると、削除マーカーが作成され、オブジェクトは非カレントになります。
** 20日後、非現行オブジェクトは削除され、削除マーカーは期限切れとなります。
** その後まもなく、期限切れの削除マーカーが削除されます。




--
