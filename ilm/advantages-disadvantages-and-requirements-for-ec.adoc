= StorageGRID におけるイレイジャー コーディングの利点、欠点、および要件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
レプリケーションとイレイジャー コーディングのどちらを使用してオブジェクト データの損失を防ぐかを決定する前に、イレイジャー コーディングの利点、欠点、および要件を理解しておく必要があります。



[[advantages-of-erasure-coding]]
== イレイジャー コーディングの利点

複製と比較すると、イレイジャー コーディングは信頼性、可用性、およびストレージ効率が向上します。

* *信頼性*：データ損失なしで耐えられる同時障害の数によって測定されます。
+
** レプリケーション：同一のオブジェクトコピーが複数、異なるノードおよびサイト間で保存されます。
** イレイジャー コーディング：オブジェクトはデータフラグメントとパリティフラグメントにエンコードされ、多数のノードとサイトに分散されます。この分散配置により、サイト障害とノード障害の両方から保護されます。


* *可用性*：ストレージノードが故障したりアクセスできなくなった場合に、オブジェクトを取得できる能力。レプリケーションと比較すると、イレイジャー コーディングは同等のストレージコストで可用性を向上させます。
* *ストレージ効率*：同等の可用性と信頼性の場合、イレイジャー コーディングされたオブジェクトは、複製されたオブジェクトよりもディスク容量の使用量が少なくなります。例えば、10 MB のオブジェクトを 2 つのサイトに複製すると 20 MB のディスク容量（2 つのコピー）を消費しますが、6+3 イレイジャー コーディング方式で 3 つのサイトにイレイジャー コーディングされたオブジェクトは、15 MB のディスク容量しか消費しません。
+

NOTE: イレイジャー コーディング オブジェクトのディスク容量は、オブジェクトサイズにストレージ オーバーヘッドを加えた値として計算されます。ストレージ オーバーヘッドのパーセンテージは、パリティフラグメントの数をデータフラグメントの数で割った値です。





[[disadvantages-of-erasure-coding]]
== イレイジャー コーディングのデメリット

複製と比較すると、イレイジャー コーディングには次のような欠点があります。

* イレイジャー コーディング方式によっては、ストレージノードとサイトの数を増やすことが推奨されます。一方、オブジェクトデータをレプリケートする場合は、コピーごとにストレージノードが1つあれば十分です。link:what-erasure-coding-schemes-are.html#erasure-coding-schemes-for-storage-pools-containing-three-or-more-sites["3つ以上のサイトを含むストレージプールのイレイジャー コーディング方式"]およびlink:what-erasure-coding-schemes-are.html#erasure-coding-schemes-for-one-site-storage-pools["単一サイトストレージプール向けのイレイジャー コーディング方式"]を参照してください。
* ストレージ拡張に伴うコストと複雑さが増大します。レプリケーションを使用するデプロイメントを拡張するには、オブジェクトのコピーが作成されるすべての場所にストレージ容量を追加します。イレイジャー コーディングを使用するデプロイメントを拡張するには、使用されているイレイジャー コーディング方式と、既存のストレージノードの使用状況の両方を考慮する必要があります。例えば、既存のノードが 100% 満杯になるまで待つ場合は、少なくとも `k+m`ストレージノードを追加する必要がありますが、既存のノードが 70% の時点で拡張すれば、サイトごとに 2 つのノードを追加しても、使用可能なストレージ容量を最大限に活用できます。詳細については、link:../expand/adding-storage-capacity-for-erasure-coded-objects.html["イレイジャー コーディング オブジェクト用のストレージ容量を追加する"]を参照してください。
* 地理的に分散した複数のサイトにわたってイレイジャー コーディングを使用すると、取得レイテンシが増加します。イレイジャー コーディングされ、複数のリモートサイトに分散されたオブジェクトのオブジェクト フラグメントは、レプリケートされてローカル（クライアントが接続するのと同じサイト）で利用可能なオブジェクトよりも、WAN 接続経由での取得に時間がかかります。
* 地理的に分散したサイト全体でイレイジャー コーディングを使用すると、特に頻繁に取得されるオブジェクトや WAN ネットワーク接続を介したオブジェクトの修復において、取得および修復のための WAN ネットワーク トラフィックの使用量が増加します。
* 複数のサイト間でイレイジャー コーディングを使用する場合、サイト間のネットワーク遅延が増加するにつれて、最大オブジェクトスループットは急激に低下します。この低下は、TCP ネットワークスループットの低下によるもので、StorageGRID システムがオブジェクトフラグメントを保存および取得する速度に影響します。
* コンピューティングリソースの使用率が高くなります。




[[when-to-use-erasure-coding]]
== イレイジャー コーディングを使用する場合

以下の要件に対してイレイジャー コーディングを使用する場合：

* サイズが1MBを超えるオブジェクト。
+

NOTE: イレイジャー コーディングは、1 MB を超えるオブジェクトに最適です。非常に小さなイレイジャー コーディング フラグメントを管理するオーバーヘッドを回避するために、200 KB 未満のオブジェクトにはイレイジャー コーディングを使用しないでください。

* 使用頻度の低いコンテンツの長期保存またはコールドストレージ。
* 高いデータ可用性と信頼性。
* サイト全体およびノードの完全な障害に対する保護。
* ストレージ効率。
* 複数のレプリケートされたコピーではなく、単一のイレイジャー コーディングされたコピーのみで効率的なデータ保護を必要とする、単一サイト展開。
* 複数拠点展開において、拠点間のレイテンシが100ミリ秒未満である場合。
