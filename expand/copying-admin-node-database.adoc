= StorageGRID で Admin Node データベースを新しい Admin Node にコピーする
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
拡張手順によって管理ノードを追加する場合、オプションでプライマリ管理ノードから新しい管理ノードにデータベースをコピーできます。データベースをコピーすることで、属性、アラート、警告に関する履歴データを保持できます。

.開始する前に
* 管理者ノードを追加するために必要な拡張手順が完了しました。
* あなたは `Passwords.txt`ファイルを持っています。
* プロビジョニングパスフレーズをお持ちです。


.タスク概要
StorageGRIDソフトウェアのアクティベーションプロセスにより、拡張管理ノード上にNMSサービス用の空のデータベースが作成されます。拡張管理ノードでNMSサービスが起動すると、現在システムの一部となっているサーバーやサービス、または後から追加されるサーバーやサービスに関する情報が記録されます。この管理ノードデータベースには、以下の情報が含まれています：

* アラート履歴
* ノードページの従来型チャートで使用される履歴属性データ


管理ノードのデータベースがノード間で一貫性を保つようにするには、プライマリ管理ノードから拡張管理ノードにデータベースをコピーすることができます。


NOTE: プライマリ管理ノード（ソース管理ノード）から拡張管理ノードへのデータベースのコピーには、完了までに数時間かかる場合があります。この期間中は、グリッドマネージャーにアクセスできません。

データベースをコピーする前に、以下の手順に従って、プライマリ管理ノードと拡張管理ノードの両方で MI サービスと Management API サービスを停止してください。

.手順
. プライマリ管理ノードで以下の手順を実行します。
+
.. 管理ノードにログインします。
+
... 次のコマンドを入力します： `ssh admin@_grid_node_IP_`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
... 以下のコマンドを入力して root に切り替えます： `su -`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。


.. 次のコマンドを実行します。 `recover-access-points`
.. プロビジョニングパスフレーズを入力してください。
.. MIサービスを停止します： `service mi stop`
.. 管理アプリケーションプログラミングインターフェース（mgmt-api）サービスを停止します： `service mgmt-api stop`


. 拡張管理ノードで以下の手順を実行します。
+
.. 拡張管理ノードにログインします。
+
... 次のコマンドを入力します： `ssh admin@_grid_node_IP_`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
... 以下のコマンドを入力して root に切り替えます： `su -`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。


.. MIサービスを停止します： `service mi stop`
.. mgmt-apiサービスを停止します： `service mgmt-api stop`
.. SSHエージェントにSSH秘密鍵を追加します。入力：``ssh-add``
..  `Passwords.txt`ファイルに記載されている SSH アクセスパスワードを入力してください。
.. ソース管理ノードから拡張管理ノードへデータベースをコピーします： `/usr/local/mi/bin/mi-clone-db.sh _Source_Admin_Node_IP_`
.. プロンプトが表示されたら、拡張アドミンノード上のMIデータベースを上書きすることを確認してください。
+
データベースとその履歴データは拡張管理ノードにコピーされます。コピー操作が完了すると、スクリプトは拡張管理ノードを起動します。

.. 他のサーバーへのパスワードなしアクセスが不要になった場合は、SSHエージェントから秘密鍵を削除してください。入力：``ssh-add -D``


. プライマリ管理ノードでサービスを再起動します。 `service servermanager start`
