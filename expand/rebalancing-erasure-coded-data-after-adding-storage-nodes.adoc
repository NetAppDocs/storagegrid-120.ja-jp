= StorageGRID システムにノードを追加した後、イレイジャー コーディング データをリバランスします
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージノードを追加したら、イレイジャー コーディング（EC）リバランス手順を使用して、既存および新規のストレージノード間でイレイジャー コーディングされたフラグメントを再分配できます。

.開始する前に
* 新しいストレージノードを追加するための拡張手順が完了しました。
* link:considerations-for-rebalancing-erasure-coded-data.html["イレイジャー コーディング データの再バランスに関する考慮事項"]をレビューしました。
* この手順ではレプリケートされたオブジェクトデータは移動されないこと、またECリバランス手順でもレプリケートされたデータは移動されないことを理解してください。ただし、ECデータの移動先を決定する際には、レプリケートされたデータも考慮されます。
* あなたは `Passwords.txt`ファイルを持っています。


.この手順を実行すると何が起こるか
手順を開始する前に、以下の点にご注意ください。

* 1つ以上のボリュームがオフライン（マウントされていない）状態である場合、またはオンライン（マウントされている）であってもエラー状態である場合は、EC リバランス手順は開始されません。
* ECリバランス手順では、一時的に大量のストレージが確保されます。ストレージに関するアラートが発動する可能性がありますが、リバランスが完了すれば解消されます。予約に必要なストレージ容量が不足している場合、ECリバランス手順は失敗します。ストレージ予約は、ECリバランス手順が完了した時点で、手順の成否に関わらず解放されます。
* ECリバランス処理中にボリュームがオフラインになった場合、リバランス処理は終了します。すでに移動されたデータフラグメントは新しい場所にそのまま残り、データが失われることはありません。
+
すべてのボリュームがオンラインに戻ったら、手順を再度実行できます。

* ECリバランス手順の実行中は、ILM操作およびS3クライアント操作のパフォーマンスに影響が出る可能性があります。
+

NOTE: S3 API を使用したオブジェクト（またはオブジェクトの一部）のアップロード操作は、完了までに 24 時間以上かかる場合、EC のリバランス処理中に失敗する可能性があります。該当する ILM ルールで、取り込み時にバランス型または厳密型の配置が使用されている場合、長時間の PUT 操作は失敗します。以下のエラーが報告されます： `500 Internal Server Error`

* *作業完了条件*。ECリバランス手順は、以下のいずれかに該当する場合に完了したとみなされます。
+
** これ以上、イレイジャー コーディングされたデータを転送することはできません。
** すべてのノードのデータは、目標データパーティションとの偏差が5%以内です。
** この手続きは30日間実施されています。




.手順
. [[review_object_storage]]リバランスを予定しているサイトの現在のオブジェクトストレージの詳細を確認してください。
+
.. * Nodes * を選択します。
.. サイト内の最初のストレージノードを選択します。
.. 「ストレージ」タブを選択します。
.. ストレージノード上のレプリケートされたデータとイレイジャー コーディングされたデータの現在の量を確認するには、「使用ストレージ量 - オブジェクトデータ」グラフにカーソルを合わせます。
.. サイト内の他のストレージノードを表示するには、これらの手順を繰り返してください。


. プライマリ管理ノードにログインします。
+
.. 次のコマンドを入力します： `ssh admin@_primary_Admin_Node_IP_`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
.. 以下のコマンドを入力して root に切り替えます： `su -`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
+
rootとしてログインすると、プロンプトが `$`から `#`に変わります。



. 手順を開始します。
+
`rebalance-data start --site "_site-name_"`

+
「_site-name_」には、新しいストレージノードを追加した最初のサイトを指定します。 `site-name`を引用符で囲みます。

+
ECリバランス手順が開始され、ジョブIDが返されます。

. ジョブIDをコピーします。
. [[view-status]]ECリバランス手順のステータスを監視します。
+
** 単一の EC リバランス手順のステータスを表示するには：
+
`rebalance-data status --job-id _job-id_`

+
 `_job-id_`には、手順を開始したときに返された ID を指定してください。

** 現在の EC 再調整手順および過去に完了した手順の状況を確認するには：
+
`rebalance-data status`

+
[NOTE]
====
rebalance-dataコマンドに関するヘルプを取得するには：

`rebalance-data --help`

====


. 返されたステータスに基づいて、追加の手順を実行します。
+
**  `State`が `In progress`の場合、EC リバランス処理はまだ実行中です。手順が完了するまで、定期的に監視してください。
+
サイト内のストレージノード全体におけるデータ分散状況を評価するには、「ノード」ページにアクセスしてください。

+
ECリバランス処理は、すべてのノードのデータが目標データパーティションの5%以内の偏差に収まった時点で完了とみなされ、停止します。

**  `State`が `Success`の場合、必要に応じて<<review_object_storage,オブジェクトストレージの確認>>でサイトの最新情報を確認できます。
+
イレイジャー コーディングされたデータは、サイト内のストレージノード間でよりバランスよく分散されるようになるはずです。

** もし `State`が `Failure`の場合：
+
... サイト内のすべてのストレージノードがグリッドに接続されていることを確認してください。
... これらのストレージノードに影響を与えている可能性のあるアラートがないか確認し、発生している場合は解決してください。
... ECリバランス手順を再開します。
+
`rebalance-data start –-job-id _job-id_`

... <<view-status,ステータスを表示する>>新しい手順について。 `State`がまだ `Failure`の場合は、テクニカルサポートにお問い合わせください。




. ECリバランス手順によって過大な負荷が発生している場合（例えば、データ取り込み操作に影響が出ている場合）、手順を一時停止してください。
+
`rebalance-data pause --job-id _job-id_`

. EC リバランス手順を終了する必要がある場合（たとえば、StorageGRID ソフトウェアのアップグレードを実行する場合）、以下を入力してください：
+
`rebalance-data terminate --job-id _job-id_`

+

NOTE: ECリバランス手順を終了すると、既に移動されたデータフラグメントは新しい場所に残ります。データは元の場所に戻されません。

. 複数のサイトでイレイジャー コーディングを使用している場合は、影響を受ける他のすべてのサイトに対してもこの手順を実行してください。
