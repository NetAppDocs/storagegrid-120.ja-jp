= StorageGRID におけるイレイジャー コーディング（EC）データのストレージ拡張計画
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ILMポリシーにイレイジャー コーディングコピーを作成するルールが含まれている場合は、新しいストレージを追加する場所と時期を計画する必要があります。追加するストレージ容量とその追加タイミングは、グリッドの利用可能なストレージ容量に影響を与える可能性があります。

ストレージ拡張を計画する最初のステップは、ILMポリシーの中でイレイジャー コーディングオブジェクトを作成するルールを確認することです。StorageGRIDはイレイジャー コーディングオブジェクトごとに _k+m_ 個のフラグメントを作成し、各フラグメントを異なるストレージノードに格納するため、拡張後に新しいイレイジャー コーディングデータを格納するためのスペースを持つストレージノードが少なくとも _k+m_ 個確保されていることを確認する必要があります。イレイジャー コーディングプロファイルがサイト損失保護機能を提供する場合は、各サイトにストレージを追加する必要があります。イレイジャー コーディングプロファイルの詳細については、link:../ilm/what-erasure-coding-schemes-are.html["イレイジャー コーディング方式とは何ですか？"]を参照してください。

追加する必要のあるノードの数は、拡張を実行する時点で既存のノードがどの程度使用されているかにも左右されます。



[[general-recommendation-for-adding-storage-capacity-for-erasure-coded-objects]]
== イレイジャー コーディングオブジェクトのストレージ容量を追加するための一般的な推奨事項

詳細な計算を避けたい場合は、既存のストレージノードの容量が70%に達した時点で、サイトごとに2つのストレージノードを追加することができます。

この一般的な推奨事項は、単一サイトグリッドと、イレイジャー コーディングがサイト損失保護を提供するグリッドの両方において、幅広いイレイジャー コーディングスキームにわたって適切な結果をもたらします。

この推奨事項に至った要因をより深く理解するため、またはサイト向けのより正確な計画を策定するには、link:considerations-for-rebalancing-erasure-coded-data.html["イレイジャー コーディングデータのリバランスに関する考慮事項"]を参照してください。お客様の状況に最適化されたカスタム推奨事項については、NetApp プロフェッショナルサービスコンサルタントにお問い合わせください。
