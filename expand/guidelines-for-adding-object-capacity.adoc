= StorageGRID でオブジェクト容量を追加するためのガイドライン
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
既存のストレージノードにストレージボリュームを追加するか、既存のサイトに新しいストレージノードを追加することで、StorageGRID システムのオブジェクトストレージ容量を拡張できます。ストレージ容量は、情報ライフサイクル管理（ILM）ポリシーの要件を満たす方法で追加する必要があります。



[[guidelines-for-adding-storage-volumes]]
== ストレージボリュームを追加するためのガイドライン

既存のストレージノードにストレージボリュームを追加する前に、以下のガイドラインと制限事項を確認してください。

* 現在のILMルールを調べて、link:../expand/adding-storage-volumes-to-storage-nodes.html["ストレージボリュームを追加する"]のストレージ容量を増やすために、いつどこで実施するかを確認する必要があります（link:../ilm/what-replication-is.html["複製されたオブジェクト"]またはlink:../ilm/what-erasure-coding-schemes-are.html["消去符号化オブジェクト"]）。
* オブジェクトのメタデータはボリューム 0 にのみ保存されるため、ストレージボリュームを追加してもシステムのメタデータ容量を増やすことはできません。
* 各ソフトウェアベースのストレージノードは、最大48個のストレージボリュームをサポートできます。それ以上の容量が必要な場合は、新しいストレージノードを追加する必要があります。
* SG6060の各アプライアンスには、拡張シェルフを1台または2台追加できます。各拡張シェルフにより、ストレージボリュームが16個追加されます。拡張シェルフを2台とも取り付けた場合、SG6060は合計48個のストレージボリュームをサポートできます。
* SG6160の各アプライアンスには、拡張シェルフを1台または2台追加できます。各拡張シェルフにより、ストレージボリュームが60個追加されます。拡張シェルフを2台とも取り付けた場合、SG6160は合計180個のストレージボリュームをサポートできます。
* 他のストレージアプライアンスにストレージボリュームを追加することはできません。
* 既存のストレージボリュームのサイズを増やすことはできません。
* システムアップグレード、リカバリ操作、またはその他の拡張を実行している間は、ストレージノードにストレージボリュームを追加できません。


ストレージボリュームを追加することを決定し、ILMポリシーを満たすために拡張する必要のあるストレージノードを特定したら、ストレージノードの種類に応じた手順に従ってください。

* SG6060ストレージアプライアンスに拡張シェルフを1つまたは2つ追加するには、 https://docs.netapp.com/us-en/storagegrid-appliances/sg6000/adding-expansion-shelf-to-deployed-sg6060.html["導入済みのSG6060に拡張シェルフを追加"^]を参照してください。
* SG6160ストレージアプライアンスに拡張シェルフを1つまたは2つ追加するには、 https://docs.netapp.com/us-en/storagegrid-appliances/sg6100/adding-expansion-shelf-to-deployed-sg6160.html["導入済みのSG6160に拡張シェルフを追加"^]
* ソフトウェアベースのノードの場合は、link:adding-storage-volumes-to-storage-nodes.html["ストレージノードへのストレージボリュームの追加"]の手順に従ってください。




[[guidelines-for-adding-storage-nodes]]
== ストレージノードを追加するためのガイドライン

既存のサイトにストレージノードを追加する前に、以下のガイドラインと制限事項を確認してください。

* ストレージの空き容量を増やすためにストレージノードを追加する場所とタイミングを決定するには、現在のILMルールを精査する必要があります（link:../ilm/what-replication-is.html["複製されたオブジェクト"]またはlink:../ilm/what-erasure-coding-schemes-are.html["消去符号化オブジェクト"]）。
* 1回の拡張手順で追加できるストレージノードは10台までです。
* ストレージノードは、1回の拡張手順で複数のサイトに追加できます。
* ストレージノードやその他の種類のノードは、単一の拡張手順で追加できます。
* 拡張手順を開始する前に、復旧の一環として実行されたすべてのデータ修復操作が完了していることを確認する必要があります。link:../maintain/checking-data-repair-jobs.html["データ修復作業を確認する"]を参照してください。
* 拡張作業の前後にストレージノードを削除する必要がある場合は、1回のノード削除手順で10個を超えるストレージノードを削除しないでください。
* 基盤となるストレージのI/Oパフォーマンスを維持するために、十分な数のストレージノードを追加してください。書き込み操作は、利用可能なストレージ容量に基づいて、ストレージノード間で分散されます。拡張されたストレージノードの利用可能なストレージ容量が大幅に多い場合、それらのノードは大幅に多くの書き込みを受け取ることになります。特に、既存のストレージノードがほぼ満杯の場合、新規書き込みは拡張されたストレージノードのみに依存します。読み取りおよび削除操作は、お客様の具体的なワークロードに応じて処理されます。




[[guidelines-for-adc-service-on-storage-nodes]]
== ストレージノードにおけるADCサービスに関するガイドライン

拡張機能を構成する際には、各新規ストレージノードに管理ドメインコントローラー（ADC）サービスを含めるかどうかを選択する必要があります。ADCサービスは、グリッドサービスの場所と可用性を追跡します。

* link:../maintain/move-adc-service.html["同一サイト内のストレージノード間でADCサービスを移動する"]できます。
* StorageGRID システムでは、各サイトで常時 link:../maintain/understanding-adc-service-quorum.html["ADCサービスの定足数"] が利用可能である必要があります。
* 各サイトにおいて、少なくとも3つのストレージノードにADCサービスを搭載する必要があります。
* すべてのストレージノードにADCサービスを追加することは推奨されません。ADCサービスを過剰に含めると、ノード間の通信量が増加するため、処理速度が低下する可能性があります。
* 単一のグリッドには、ADCサービスを備えたストレージノードが48個を超えて存在してはなりません。これは、各拠点に3つのADCサービスを備えた16の拠点に相当します。
* 一般的に、新しいノードの「ADC サービス」設定を選択する際は、「自動」を選択してください。新しいノードが、ADC サービスを含む別のストレージノードを置き換える場合にのみ、「はい」を選択してください。ADC サービスが少なすぎる場合はストレージノードを廃止できないため、「はい」を選択すると、古いサービスが削除される前に新しい ADC サービスが利用可能になることが保証されます。
