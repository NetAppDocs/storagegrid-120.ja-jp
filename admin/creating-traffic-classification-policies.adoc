= StorageGRID トラフィック分類ポリシーを作成する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
監視したい場合や、必要に応じてバケット、バケット正規表現、CIDR、ロードバランサーエンドポイント、またはテナントごとにネットワーク トラフィックを制限したい場合は、トラフィック分類ポリシーを作成できます。必要に応じて、帯域幅、同時リクエスト数、またはリクエストレートに基づいて、ポリシーの制限を設定できます。

.開始する前に
* link:../admin/web-browser-requirements.html["対応ウェブブラウザ"] を使用して Grid Manager にサインインしています。
* あなたはlink:admin-group-permissions.html["ルートアクセス権限"]があります。
* 一致させたいロードバランサーのエンドポイントをすべて作成しました。
* マッチングさせたいテナントをすべて作成しました。


.手順
. *[設定]* > *[ネットワーク]* > *[トラフィック分類]* を選択します。
. *Create*を選択します。
. ポリシーの名前と説明（任意）を入力し、*続行*を選択します。
+
例えば、このトラフィック分類ポリシーが何に適用され、何を制限するかを説明してください。

. 「ルールを追加」を選択し、以下の詳細を指定して、ポリシーに一致するルールを1つ以上作成します。作成するポリシーには、少なくとも1つの一致するルールが必要です。「続行」を選択します。
+
[cols="1a,3a"]
|===
| フィールド | 説明 


 a| 
Type
 a| 
マッチングルールを適用するトラフィックの種類を選択してください。トラフィックの種類は、バケット、バケット正規表現、CIDR、ロードバランサーエンドポイント、およびテナントです。



 a| 
値に一致
 a| 
選択したタイプに一致する値を入力してください。

** バケット：バケット名を1つ以上入力してください。
** バケット正規表現：バケット名のセットに一致する正規表現を1つ以上入力します。
+
正規表現はアンカーされていません。バケット名の先頭に一致させるには ^ アンカーを使用し、名前の末尾に一致させるには $ アンカーを使用します。正規表現マッチングは、PCRE（Perl 互換正規表現）構文のサブセットをサポートしています。

** CIDR：目的のサブネットに一致する IPv4 サブネットを 1 つ以上、CIDR 表記で入力してください。
** ロードバランサーエンドポイント：エンドポイント名を選択してください。これらは、link:../admin/configuring-load-balancer-endpoints.html["ロードバランサーのエンドポイントを設定する"]で定義したロードバランサーエンドポイントです。
** テナント：テナントのマッチングにはアクセスキーIDが使用されます。リクエストにアクセスキー ID が含まれていない場合（たとえば、匿名アクセス）、アクセスされたバケットの所有権を使用してテナントが決定されます。




 a| 
逆マッチ
 a| 
定義したタイプとマッチ値に一致するトラフィックを**除く**すべてのネットワーク トラフィックに一致させる場合は、「逆マッチ」チェックボックスを選択してください。それ以外の場合は、チェックボックスをオフのままにしてください。

例えば、このポリシーをロードバランサーエンドポイントの1つを除くすべてに適用する場合は、除外するロードバランサーエンドポイントを指定し、「逆一致」を選択します。

複数のマッチャーを含むポリシーで、少なくとも1つが逆マッチャーである場合は、すべてのリクエストに一致するポリシーを作成しないように注意してください。

|===
. オプションで「制限を追加」を選択し、次の詳細を選択して、ルールに一致したネットワーク トラフィックを制御する 1 つ以上の制限を追加します。
+

NOTE: StorageGRID は、制限を追加しなくても指標を収集するため、ネットワーク トラフィックの傾向を把握できます。

+
[cols="1a,3a"]
|===
| フィールド | 説明 


 a| 
Type
 a| 
ルールに一致したネットワーク トラフィックに適用する制限の種類。例えば、帯域幅やリクエストレートを制限することができます。

*注*：総帯域幅を制限するポリシー、またはリクエストごとの帯域幅を制限するポリシーを作成できます。ただし、StorageGRID は両方の種類の帯域幅を同時に制限することはできません。集約帯域幅を使用している場合、リクエストごとの帯域幅は使用できません。逆に、リクエストごとの帯域幅が使用されている場合、集約帯域幅は使用できません。総帯域幅制限は、制限のないトラフィックにも軽微なパフォーマンス上の影響を与える可能性があります。

帯域幅制限については、StorageGRID は設定された制限の種類に最も適したポリシーを適用します。例えば、トラフィックを一方向のみに制限するポリシーを設定した場合、帯域幅制限のある追加のポリシーに一致するトラフィックが存在する場合でも、逆方向のトラフィックは無制限になります。StorageGRID は、帯域幅制限に対する「最適な」マッチングを以下の順序で実装します。

** 正確なIPアドレス（/32マスク）
** 正確なバケット名
** バケット正規表現
** テナント
** エンドポイント
** 完全一致しないCIDR（/32以外）
** 逆マッチ




 a| 
環境
 a| 
この制限がクライアントの読み取りリクエスト（GET または HEAD）に適用されるか、書き込みリクエスト（PUT、POST、または DELETE）に適用されるか。



 a| 
Value
 a| 
選択したユニットに基づいて、ネットワーク トラフィックが制限される値です。たとえば、10 と入力して MiB/s を選択すると、このルールに一致するネットワーク トラフィックが 10 MiB/s を超えないように制限されます。

*注*：単位設定によっては、使用可能な単位はバイナリ（例：GiB）または10進数（例：GB）のいずれかになります。単位設定を変更するには、グリッドマネージャーの右上にあるユーザードロップダウンを選択し、*ユーザー設定*を選択します。



 a| 
単位
 a| 
入力した値を表す単位。

|===
+
例えば、SLAティアに対して4 GB/sの帯域幅制限を設定したい場合は、GET/HEADを4 GB/s、PUT/POST/DELETEを4 GB/sとする2つの集約帯域幅制限を作成します。

. *続行*を選択します。
. トラフィック分類ポリシーを読んで確認してください。必要に応じて変更を加えるには、「前へ」ボタンを使用してください。ポリシーの内容に問題がなければ、「保存して続行」を選択してください。
+
S3クライアントのトラフィックは、トラフィック分類ポリシーに従って処理されるようになりました。



.終了後の操作
link:viewing-network-traffic-metrics.html["ネットワーク トラフィック メトリクスの表示"]ポリシーが期待どおりのトラフィック制限を適用していることを確認するため。
