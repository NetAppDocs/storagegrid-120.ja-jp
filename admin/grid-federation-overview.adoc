= StorageGRID グリッド フェデレーションについて学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
グリッドフェデレーションを使用すると、テナントを複製し、ディザスタリカバリのために2つの StorageGRID システム間でオブジェクトをレプリケートできます。



[[what-is-a-grid-federation-connection]]
== グリッドフェデレーション接続とは何ですか？

グリッドフェデレーション接続は、2つのStorageGRIDシステムの管理ノードとゲートウェイノード間の双方向の信頼できる安全な接続です。

== グリッド連携のためのワークフロー

ワークフロー図は、2つのグリッド間でグリッド連携接続を構成する手順をまとめたものです。

image:grid-federation-workflow.png["グリッドフェデレーション接続ワークフロー"]



[[considerations-and-requirements-for-grid-federation-connections]]
== グリッド連携接続に関する考慮事項と要件

* グリッドフェデレーションに使用するグリッドは、同一バージョン、またはメジャーバージョンの差が1つ以下の StorageGRID バージョンを実行している必要があります。
+
バージョン要件の詳細については、 https://library.netapp.com/ecm/ecm_download_file/ECMLP3351267["リリース ノート"^]を参照してください。NetAppアカウントでサインインするか、アカウントを作成してリリースノートにアクセスする必要があります。

* グリッドは、他のグリッドと1つ以上のグリッド連携接続を持つことができます。各グリッド連携接続は、他の接続とは独立しています。例えば、Grid 1がGrid 2と1つの接続を持ち、Grid 3ともう1つの接続を持つ場合、Grid 2とGrid 3の間には暗黙の接続は存在しません。
* グリッド連携接続は双方向です。接続が確立された後は、どちらのグリッドからでも接続を監視および管理できます。
* link:grid-federation-what-is-account-clone.html["アカウントクローン"]またはlink:grid-federation-what-is-cross-grid-replication.html["グリッド間複製"]を使用するには、グリッドフェデレーション接続が少なくとも1つ存在する必要があります。




[[networking-and-ip-address-requirements]]
=== ネットワークおよびIPアドレスの要件

* グリッドフェデレーション接続は、グリッドネットワーク、管理ネットワーク、またはクライアントネットワーク上で発生する可能性があります。
* グリッド連携接続とは、あるグリッドと別のグリッドを接続するものです。各グリッドの設定では、管理ノード、ゲートウェイノード、またはその両方で構成される、他のグリッド上のグリッドフェデレーションエンドポイントを指定します。
* ベストプラクティスは、各グリッドのゲートウェイノードと管理ノードのlink:managing-high-availability-groups.html["高可用性（HA）グループ"]を接続することです。HAグループを使用することで、ノードが利用不能になった場合でも、グリッド連携接続がオンライン状態を維持できます。いずれかのHAグループ内のアクティブなインターフェースに障害が発生した場合、接続はバックアップインターフェースを使用できます。
* 単一の管理ノードまたはゲートウェイノードのIPアドレスを使用するグリッドフェデレーション接続を作成することは推奨されません。ノードが利用不能になると、グリッドフェデレーション接続も利用不能になります。
* link:grid-federation-what-is-cross-grid-replication.html["クロスグリッド複製"]オブジェクトを扱うには、各グリッド上のストレージノードが、他のグリッド上の構成済み管理ノードとゲートウェイノードにアクセスできる必要があります。各グリッドについて、すべてのストレージノードが、接続に使用される管理ノードまたはゲートウェイノードへの高帯域幅の経路を持っていることを確認してください。




[[use-fqdns-to-load-balance-the-connection]]
=== FQDNを使用して接続の負荷分散を行う

本番環境では、完全修飾ドメイン名（FQDN）を使用して接続内の各グリッドを識別します。次に、以下のように適切な DNS エントリを作成します。

* Grid 1 の FQDN は、Grid 1 内の HA グループの 1 つ以上の仮想 IP （VIP） アドレス、または Grid 1 内の 1 つ以上の管理ノードまたはゲートウェイノードの IP アドレスにマッピングされます。
* Grid 2 の FQDN は、Grid 2 の 1 つ以上の VIP アドレス、または Grid 2 内の 1 つ以上の管理ノードもしくはゲートウェイノードの IP アドレスにマッピングされます。


複数のDNSエントリを使用する場合、接続を使用するリクエストは次のように負荷分散されます。

* 複数のHAグループのVIPアドレスにマッピングされるDNSエントリは、HAグループ内のアクティブなノード間で負荷分散されます。
* 複数の管理ノードまたはゲートウェイノードのIPアドレスにマッピングされるDNSエントリは、マッピングされたノード間で負荷分散されます。




[[port-requirements]]
=== ポートの要件

グリッドフェデレーション接続を作成する際、23000から23999までの未使用のポート番号を指定できます。この接続における両方のグリッドは、同じポートを使用します。

どちらのグリッド内のノードも、このポートを他の接続に使用しないようにしてください。



[[certificate-requirements]]
=== 証明書の要件

グリッドフェデレーション接続を構成すると、StorageGRID は SSL 証明書を 4 つ自動的に生成します。

* グリッド1からグリッド2に送信される情報を認証および暗号化するためのサーバー証明書とクライアント証明書
* グリッド2からグリッド1に送信される情報を認証および暗号化するためのサーバー証明書とクライアント証明書


image:grid-federation-certificates.png["グリッドフェデレーション証明書"]

デフォルトでは、証明書の有効期間は730日間（2年間）です。これらの証明書の有効期限が近づくと、*グリッドフェデレーション証明書の有効期限切れ*アラートが表示され、証明書のローテーションを促します。証明書のローテーションは、Grid Manager を使用して行うことができます。


CAUTION: 接続の両端にある証明書の有効期限が切れると、接続は機能しなくなります。証明書が更新されるまで、データの複製は保留状態となります。
