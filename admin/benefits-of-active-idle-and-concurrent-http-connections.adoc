= StorageGRID におけるアクティブ、アイドル、および同時 HTTP 接続の利点
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
HTTP接続の設定方法は、StorageGRIDシステムのパフォーマンスに影響を与える可能性があります。HTTP接続がアクティブかアイドルか、あるいは複数の接続が同時に存在するかによって、設定は異なります。

以下の種類のHTTP接続におけるパフォーマンス上の利点を確認できます。

* アイドル状態のHTTP接続
* アクティブなHTTP接続
* 同時HTTP接続




[[benefits-of-keeping-idle-http-connections-open]]
== アイドル状態のHTTP接続を開いたままにしておくことの利点

クライアントアプリケーションがアイドル状態のときは、後続のトランザクションを可能にするためにHTTP接続を開いたままにしておく。アイドル状態のHTTP接続は、最大10分間開いたままにしてください。StorageGRID は、10分以上開いたままアイドル状態になっているHTTP接続を自動的に閉じる場合があります。

開いているアイドル状態のHTTP接続には、以下の利点があります：

* StorageGRID システムが HTTP トランザクションを実行する必要があると判断してから、実際にトランザクションを実行できるまでの遅延が軽減されます
+
最大の利点はレイテンシの低減であり、特にTCP/IPおよびTLS接続の確立に必要な時間において顕著です。

* 以前に実行された転送データでTCP/IPスロースタートアルゴリズムを初期化することにより、データ転送速度を向上
* クライアントアプリケーションとStorageGRIDシステム間の接続を中断するいくつかの種類の障害状態の即時通知


スロースタートの利点とリソース配分のバランスを取りながら、アイドル状態の接続をどのくらいの時間開いたままにするかを決定します。



[[benefits-of-active-http-connections]]
== アクティブなHTTP接続の利点

ストレージノードに直接接続する場合、HTTP接続が継続的にトランザクションを実行する場合でも、アクティブなHTTP接続の継続時間を最大10分に制限する必要があります。

接続を維持すべき最大期間を決定することは、接続の持続性による利点と、接続を内部システムリソースに理想的に割り当てることとの間のトレードオフとなります。

ストレージノードへのクライアント接続において、アクティブなHTTP接続を制限することで、以下の利点が得られます。

* StorageGRID システム全体で最適なロード バランシングを実現します。
+
時間の経過とともに、ロード バランシング要件の変化により、HTTP接続が最適ではなくなる可能性があります。クライアントアプリケーションがトランザクションごとに個別のHTTP接続を確立する場合、システムは最高のロード バランシングを実現しますが、この方法では永続的な接続に伴う貴重な利点が失われてしまいます。

* クライアントアプリケーションが、空き容量のあるLDRサービスにHTTPトランザクションを送信できるようにします。
* メンテナンス手順を開始できるようにします。
+
一部のメンテナンス手順は、進行中のすべてのHTTP接続が完了した後にのみ開始されます。



ロード バランシングサービスへのクライアント接続において、接続の維持時間を制限することは、一部のメンテナンス手順を迅速に開始するために役立ちます。クライアント接続の継続時間に制限がない場合、アクティブな接続が自動的に終了するまでに数分かかることがあります。



[[benefits-of-concurrent-http-connections]]
== 同時HTTP接続の利点

並列処理を可能にしてパフォーマンスを向上させるために、StorageGRID システムへの複数の TCP/IP 接続を開いたままにしておく必要があります。並列接続の最適な数は、さまざまな要因によって決まります。

同時HTTP接続には、以下の利点があります。

* 遅延の低減
+
他の取引が完了するのを待つことなく、取引をすぐに開始できます。

* スループットの向上
+
StorageGRID システムは並列トランザクションを実行し、総トランザクションスループットを向上させることができます。



クライアントアプリケーションは、複数のHTTP接続を確立する必要があります。クライアントアプリケーションがトランザクションを実行する必要がある場合、現在トランザクションを処理していない確立済みの接続を選択して、すぐに使用することができます。

各 StorageGRID システムのトポロジーは、同時トランザクションと接続に対して異なる最大スループットを持ちます。ピークスループットは、コンピューティング、ネットワーク、ストレージリソース、WAN リンク、および StorageGRID システムがサポートするサーバー、サービス、アプリケーションの数によって異なります。

StorageGRIDシステムは多くの場合、複数のクライアントアプリケーションをサポートしています。同時接続の最大数を決定する際には、この点に留意してください。クライアントアプリケーションが、それぞれStorageGRIDシステムへの接続を確立する複数のソフトウェアエンティティで構成されている場合は、エンティティ間のすべての接続を合計してください。次のような状況では、同時接続の最大数を調整する必要がある場合があります。

* StorageGRID システムのトポロジーは、システムがサポートできる同時トランザクション数と接続数の最大数に影響します。
* 帯域幅が限られたネットワーク上で StorageGRID システムと通信するクライアントアプリケーションは、個々のトランザクションが妥当な時間内に完了するよう、同時実行の度合いを下げる必要がある場合があります。
* 多くのクライアントアプリケーションが StorageGRID システムを共有している場合は、システムの制限を超えないように、並行処理の度合いを下げる必要があります。




[[separation-of-http-connection-pools-for-read-and-write-operations]]
== 読み取り操作と書き込み操作のためのHTTP接続プールの分離

読み取り操作と書き込み操作にそれぞれ別のHTTP接続プールを使用し、各操作にプールのどの部分を使用するかを制御できます。HTTP接続を複数のプールに分けることで、トランザクションをより適切に制御し、ロード バランシングを行うことができます。

クライアントアプリケーションは、取得（読み取り）が主体となるロード、または保存（書き込み）が主体となるロードを作成できます。読み取りトランザクションと書き込みトランザクション用にHTTP接続のプールを分けることで、それぞれのプールのうち、読み取りトランザクションまたは書き込みトランザクションに割り当てる割合を調整できます。
