= StorageGRIDホットフィックス手順
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ソフトウェアの問題が機能リリース間で検出および解決された場合、StorageGRID システムにホットフィックスを適用する必要がある場合があります。

StorageGRID ホットフィックスには、機能リリースやパッチリリースとは別に提供されるソフトウェアの変更が含まれています。同様の変更は今後のリリースにも含まれる予定です。さらに、各ホットフィックスリリースには、その機能またはパッチリリースに含まれる以前のすべてのホットフィックスがまとめられています。



[[considerations-for-applying-a-hotfix]]
== ホットフィックスを適用する際の考慮事項

別のメンテナンス手順が実行されているときは、StorageGRID ホットフィックスを適用できません。たとえば、廃止、拡張、または復旧手順の実行中は、ホットフィックスを適用できません。


NOTE: ノードまたはサイトの廃止手順が一時停止されている場合は、安全にホットフィックスを適用できます。さらに、StorageGRID アップグレード手順の最終段階でホットフィックスを適用できる場合があります。詳細については、StorageGRID ソフトウェアのアップグレード手順を参照してください。

グリッドマネージャーでホットフィックスをアップロードすると、そのホットフィックスはプライマリ管理ノードに自動的に適用されます。その後、StorageGRID システム内の残りのノードへのホットフィックスの適用を承認できます。

ホットフィックスが1つ以上のノードに適用されなかった場合、失敗の理由はホットフィックス進行状況テーブルの「詳細」列に表示されます。失敗の原因となった問題を解決してから、プロセス全体をやり直す必要があります。以前にホットフィックスの適用に成功したノードは、以降の適用ではスキップされます。すべてのノードが更新されるまで、ホットフィックス処理を必要なだけ何度でも安全に再試行できます。アプリケーションを完了するには、ホットフィックスをすべてのグリッドノードに正常にインストールする必要があります。

グリッドノードは新しいホットフィックスバージョンで更新されますが、ホットフィックスによる実際の変更は、特定の種類のノード上の特定のサービスにのみ影響する場合があります。たとえば、ホットフィックスがストレージノード上の LDR サービスにのみ影響する場合があります。



[[how-hotfixes-are-applied-for-recovery-and-expansion]]
== 復旧と拡張のためのホットフィックスの適用方法

グリッドにホットフィックスが適用されると、プライマリ管理ノードは、復旧操作によって復元されたノード、または拡張によって追加されたノードに、同じホットフィックスバージョンを自動的にインストールします。

ただし、プライマリ管理ノードを復旧する必要がある場合は、正しい StorageGRID リリースを手動でインストールしてから、ホットフィックスを適用する必要があります。プライマリ管理ノードの最終的な StorageGRID バージョンは、グリッド内の他のノードのバージョンと一致している必要があります。

次の例は、プライマリ管理ノードを復旧する際にホットフィックスを適用する方法を示しています。

. グリッドが最新のホットフィックスが適用された StorageGRID 11._A.B_ バージョンで稼働していると仮定します。「グリッドバージョン」は 11._A.B.y_ です。
. プライマリ管理ノードが故障しました。
. StorageGRID 11._A.B_ を使用してプライマリ管理ノードを再デプロイし、リカバリ手順を実行します。
+

NOTE: グリッドのバージョンに合わせる必要がある場合は、ノードをデプロイする際にマイナーリリースを使用できます。最初にメジャーリリースをデプロイする必要はありません。

. 次に、プライマリ管理ノードにホットフィックス 11._A.B.y_ を適用します。


詳細については、link:configuring-replacement-primary-admin-node.html["代替プライマリ管理ノードを構成する"]を参照してください。
