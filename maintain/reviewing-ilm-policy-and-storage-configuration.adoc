= StorageGRID ILM ポリシーとストレージ構成を確認する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージノードを廃止する予定がある場合は、廃止プロセスを開始する前に、StorageGRID システムの ILM ポリシーを確認してください。

廃止措置の際、すべてのオブジェクトデータは廃止対象のストレージノードから他のストレージノードに移行されます。


NOTE: 廃止措置期間中に適用されるILMポリシーが、廃止措置後も適用されます。廃止措置を開始する前と完了後の両方において、このポリシーがお客様のデータ要件を満たしていることを確認する必要があります。

それぞれのlink:../ilm/creating-ilm-policy.html["アクティブなILMポリシー"]のルールを確認し、StorageGRID システムがストレージノードの廃止に対応するために、適切な種類の容量を適切な場所に引き続き確保できるようにしてください。

次の点を考慮してください。

* ILM評価サービスが、ILMルールを満たすようにオブジェクトデータをコピーすることは可能でしょうか？
* 廃止作業中にサイトが一時的に利用できなくなった場合はどうなりますか？別の場所にコピーを追加作成することは可能ですか？
* 廃止措置プロセスは、コンテンツの最終的な配布にどのような影響を与えますか？link:consolidating-storage-nodes.html["ストレージノードを統合する"]に記載されているとおり、古いものを廃止する前にlink:../expand/index.html["新しいストレージノードを追加する"]する必要があります。より小型のストレージノードを廃止した後、より大型の代替ストレージノードを追加する場合、古いストレージノードは容量がほぼ満杯になっている可能性があり、新しいストレージノードにはほとんどコンテンツが存在しない可能性があります。そうなると、新しいオブジェクトデータに対する書き込み操作のほとんどが新しいストレージノードに向けられることになり、システム全体の運用効率が低下します。
* システムは、常にアクティブなILMポリシーを満たすのに十分なストレージノードを備えているでしょうか？
+

NOTE: 満たされないILMポリシーはバックログやアラートにつながり、StorageGRIDシステムの運用を停止させる可能性があります。



表に記載されている領域を評価することにより、廃止プロセスによって生じる予定のトポロジーがILMポリシーを満たしていることを確認します。

[cols="1a,2a"]
|===
| 評価対象領域 | 考慮すべき事項 


 a| 
使用可能容量
 a| 
廃止予定のストレージノードに現在保存されているオブジェクトデータの永続的なコピーを含む、StorageGRID システムに保存されているすべてのオブジェクトデータを格納するのに十分なストレージ容量はありますか？

廃止措置完了後、妥当な期間にわたって、予想される保存オブジェクトデータの増加に対応できる十分な容量は確保されますか？



 a| 
保管場所
 a| 
StorageGRID システム全体に十分な容量が残っている場合、その容量は StorageGRID システムのビジネスルールを満たすために適切な場所に配置されていますか？



 a| 
ストレージ タイプ
 a| 
廃止措置完了後、適切な種類のストレージは十分に確保されますか？

例えば、ILMルールでは、コンテンツの古さに応じて、コンテンツをある種類のストレージから別の種類のストレージに移動させる場合があります。この場合、StorageGRID システムの最終構成において、適切なタイプのストレージが十分に利用可能であることを確認する必要があります。

|===
