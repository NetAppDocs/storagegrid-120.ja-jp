= プライマリ管理ノードの復旧時にStorageGRID管理ノードデータベースをリストアする
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
障害が発生したプライマリ管理ノード上の属性とアラートに関する履歴データを保持する場合は、管理ノードのデータベースを復元できます。このデータベースを復元できるのは、StorageGRID システムに別の管理ノードが含まれている場合のみです。

.開始する前に
* 復旧した管理ノードはインストールされ、稼働中です。
* StorageGRID システムには、少なくとも2つの管理ノードが含まれています。
* あなたは `Passwords.txt`ファイルを持っています。
* プロビジョニングパスフレーズをお持ちです。


.タスク概要
管理ノードが故障した場合、その管理ノードのデータベースに保存されている履歴データは失われます。このデータベースには以下の情報が含まれています：

* アラート履歴
* ノードページの従来型チャートで使用される履歴属性データ


管理ノードを復旧すると、ソフトウェアのインストールプロセスによって、復旧されたノード上に空の管理ノードデータベースが作成されます。しかし、新しいデータベースには、現在システムの一部となっている、または今後追加されるサーバーとサービスの情報のみが含まれています。

プライマリ管理ノードを復元した場合、StorageGRID システムに別の管理ノードがある場合は、プライマリではない管理ノード（_ソース管理ノード_）から復旧したプライマリ管理ノードに管理ノードデータベースをコピーすることで、履歴情報を復元できます。システムにプライマリ管理ノードしかない場合、管理ノードのデータベースを復元することはできません。


NOTE: 管理ノードのデータベースのコピーには数時間かかる場合があります。ソース管理ノードでサービスが停止している間は、Grid Managerの一部の機能が利用できなくなります。

.手順
. ソース管理ノードにログインします：
+
.. 次のコマンドを入力します： `ssh admin@_grid_node_IP_`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
.. 以下のコマンドを入力して root に切り替えます： `su -`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。


. ソース管理ノードから、MI サービスを停止します： `service mi stop`
. ソース管理ノードから、管理アプリケーションプログラムインターフェース（mgmt-api）サービスを停止します： `service mgmt-api stop`
. 復旧した管理ノードで、以下の手順を実行します。
+
.. 復旧した管理ノードにログインします。
+
... 次のコマンドを入力します： `ssh admin@_grid_node_IP_`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
... 以下のコマンドを入力して root に切り替えます： `su -`
...  `Passwords.txt`ファイルに記載されているパスワードを入力してください。


.. MIサービスを停止します： `service mi stop`
.. mgmt-apiサービスを停止します： `service mgmt-api stop`
.. SSHエージェントにSSH秘密鍵を追加します。入力：``ssh-add``
..  `Passwords.txt`ファイルに記載されている SSH アクセスパスワードを入力してください。
.. ソース管理ノードから復旧済み管理ノードへデータベースをコピーします： `/usr/local/mi/bin/mi-clone-db.sh Source_Admin_Node_IP`
.. プロンプトが表示されたら、復旧した管理ノード上の MI データベースを上書きすることを確認します。
+
データベースとその履歴データは、復旧した管理ノードにコピーされます。コピー操作が完了すると、スクリプトは復旧した管理ノードを起動します。

.. 他のサーバーへのパスワードなしアクセスが不要になった場合は、SSHエージェントから秘密鍵を削除してください。入力：``ssh-add -D``


. ソース管理ノードでサービスを再起動します。 `service servermanager start`
