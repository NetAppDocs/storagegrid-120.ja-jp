= StorageGRIDストレージノードのシステムドライブ復旧に関する警告
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージノードの障害が発生したシステムドライブを復旧する前に、一般的な link:warnings-and-considerations-for-grid-node-recovery.html["グリッドノード復旧に関する警告と考慮事項"] と以下の具体的な警告事項を確認してください。

ストレージノードには、オブジェクトのメタデータを含む Cassandra データベースが搭載されています。Cassandra データベースは、次のような場合に再構築される可能性があります：

* ストレージボリュームに障害が発生し、復旧されました。
* システムドライブおよび1つ以上のストレージボリュームに障害が発生し、その後復旧されました。


Cassandraが再構築される際、システムは他のストレージノードからの情報を使用します。Cassandraが最近再構築された場合、Cassandraのデータはグリッド全体でまだ一貫性がない可能性があります。ストレージノードが多数オフラインになっている場合：

* Cassandraのデータの一部が利用できない場合があります。
* データ損失が発生する可能性があります。



CAUTION: 複数のストレージノードが故障（またはオフライン）している場合は、テクニカルサポートにお問い合わせください。以下の復旧手順は実行しないでください。データ損失が発生する可能性があります。詳細については、link:how-site-recovery-is-performed-by-technical-support.html["テクニカルサポートがサイトを復旧する方法"]を参照してください。


CAUTION: このストレージノードが、障害が発生したストレージボリュームを持つ別のストレージノードによるオブジェクトの取得を可能にするために読み取り専用メンテナンスモードになっている場合は、この障害が発生したストレージノードを復旧する前に、障害が発生したストレージボリュームを持つストレージノード上のボリュームを復旧してください。link:recovering-from-storage-volume-failure-where-system-drive-is-intact.html["システムドライブが無事な状態でストレージボリュームの障害から復旧する"]の手順を参照してください。


CAUTION: ILMルールが複製コピーを1つだけ保存するように構成されていて、そのコピーが障害が発生したストレージボリューム上に存在する場合、オブジェクトを復旧することはできません。
