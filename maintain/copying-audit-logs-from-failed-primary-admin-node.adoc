= 障害が発生したプライマリStorageGRID管理ノードから監査ログをコピーする
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
障害が発生したプライマリ管理ノードから監査ログをコピーできる場合は、グリッドのシステムアクティビティと使用状況の記録を維持するために、それらを保存する必要があります。復旧したプライマリ管理ノードが起動して稼働状態になった後、保存しておいた監査ログを復元できます。

.タスク概要
この手順では、障害が発生した管理ノードから監査ログファイルを、別のグリッドノード上の一時的な場所にコピーします。これらの保存された監査ログは、交換後の管理ノードにコピーできます。監査ログは新しい管理ノードに自動的にコピーされません。

障害の種類によっては、障害が発生した管理ノードから監査ログをコピーできない場合があります。デプロイメントに管理ノードが1つしかない場合、復旧した管理ノードは新しい空のファイルに監査ログへのイベントの記録を開始し、以前に記録されたデータは失われます。デプロイメントに複数の管理ノードが含まれている場合、別の管理ノードから監査ログを復元できます。


NOTE: 障害が発生した管理ノードで監査ログに現在アクセスできない場合でも、ホストの復旧後など、後でアクセスできるようになる可能性があります。

.手順
. 可能であれば、障害が発生したプライマリ管理ノードにログインしてください。それ以外の場合は、利用可能な管理ノードにログインしてください。
+
.. 次のコマンドを入力します： `ssh admin@_grid_node_IP_`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
.. 以下のコマンドを入力して root に切り替えます： `su -`
..  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
+
rootとしてログインすると、プロンプトが `$`から `#`に変わります。



. 新しいログファイルが作成されないように、AMSサービスを停止してください。``service ams stop``
. 監査エクスポートディレクトリに移動します。
+
`cd /var/local/audit/export`

+
（または `cd /var/local/log`（以前のシステムでは））

. ソースログファイルの名前を、一意の番号付きファイル名に変更してください。
+
[NOTE]
====
** ログファイルが `/var/local/audit/export`ディレクトリにある場合、その名前は `audit.log`です。
** ログファイルが `/var/local/log`ディレクトリにある場合、その名前は `localaudit.log`です。


====
+
たとえば、 `localaudit.log`ファイルの名前を `2025-10-22.txt.1`に変更します。

+
[listing]
----
ls -l
mv localaudit.log 2025-10-22.txt.1
----
. AMSサービスを再起動します： `service ams start`
. すべての監査ログファイルを別のグリッドノード上の一時的な場所にコピーするためのディレクトリを作成します： `ssh admin@_grid_node_IP_ mkdir -p /var/local/tmp/saved-audit-logs`
+
プロンプトが表示されたら、管理者のパスワードを入力してください。

. すべての監査ログファイルを一時的な場所にコピーします： `scp -p * admin@_grid_node_IP_:/var/local/tmp/saved-audit-logs`
+
プロンプトが表示されたら、管理者のパスワードを入力してください。

. rootユーザーとしてログアウトする： `exit`
