= StorageGRIDストレージボリュームのリカバリに関する警告
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージノードの障害が発生したストレージボリュームを復旧する前に、以下の警告事項を確認してください。

ストレージノード内のストレージボリューム（またはレンジDB）は、ボリュームIDと呼ばれる16進数で識別されます。例えば、0000は第1ボリューム、000Fは第16ボリュームです。各ストレージノード上の最初のオブジェクトストア（ボリューム0）は、オブジェクトのメタデータと Cassandra データベース操作のために最大 4 TB の容量を使用します。そのボリューム上の残りの容量は、オブジェクトデータに使用されます。その他のストレージボリュームはすべて、オブジェクトデータ専用に使用されます。

Cassandra データベースは、以下の場合にボリューム復旧手順の一環として再構築される可能性があります。

* ボリューム0で障害が発生しましたが、復旧されました。
* システムドライブおよび1つ以上のストレージボリュームに障害が発生し、その後復旧されました。


Cassandraが再構築される際、システムは他のストレージノードからの情報を使用します。Cassandraが最近再構築された場合、Cassandraのデータはグリッド全体でまだ一貫性がない可能性があります。ストレージノードが多数オフラインになっている場合：

* Cassandraのデータの一部が利用できない場合があります。
* データ損失が発生する可能性があります。



CAUTION: 複数のストレージノードが故障（またはオフライン）している場合は、テクニカルサポートにお問い合わせください。以下の復旧手順は実行しないでください。データ損失が発生する可能性があります。詳細については、link:how-site-recovery-is-performed-by-technical-support.html["テクニカルサポートがサイトを復旧する方法"]を参照してください。


CAUTION: ILMルールが複製されたコピーを1つだけ保存するように構成されていて、そのコピーが障害が発生したストレージボリューム上に存在する場合、オブジェクトを復旧することはできません。
