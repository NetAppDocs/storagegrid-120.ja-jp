= StorageGRIDノード復旧手順を選択
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
障害が発生したノードの種類に応じて、適切な復旧手順を選択する必要があります。

[cols="1a,2a"]
|===
| グリッドノード | 回復手順 


 a| 
複数のストレージノード
 a| 
技術サポートにお問い合わせください。複数のストレージノードが故障した場合、データ損失につながる可能性のあるデータベースの不整合を防ぐため、技術サポートによる復旧支援が必要となります。サイト復旧手順が必要になる場合があります。

link:how-site-recovery-is-performed-by-technical-support.html["テクニカルサポートがサイトを復旧する方法"]



 a| 
単一のストレージノード
 a| 
ストレージノードの復旧手順は、障害の種類と継続時間によって異なります。

link:recovering-from-storage-node-failures.html["ストレージノードの障害から復旧する"]



 a| 
管理ノード
 a| 
管理ノードの復旧手順は、プライマリ管理ノードを復旧する必要があるか、プライマリ以外の管理ノードを復旧する必要があるかによって異なります。

link:recovering-from-admin-node-failures.html["管理ノードの障害から復旧する"]



 a| 
ゲートウェイ ノード
 a| 
link:replacing-gateway-node.html["ゲートウェイノードの障害から復旧する"]



 a| 
アーカイブ ノード
 a| 
https://docs.netapp.com/us-en/storagegrid-118/maintain/recovering-from-archive-node-failures.html["アーカイブノードの障害から復旧する（StorageGRID 11.8 ドキュメントサイト）"^]

|===

NOTE: 複数のグリッドノードをホストしているサーバーが故障した場合、ノードは任意の順序で復旧できます。ただし、障害が発生したサーバーがプライマリ管理ノードをホストしている場合は、まずそのノードを復旧する必要があります。プライマリ管理ノードを最初に復旧することで、他のノードの復旧がプライマリ管理ノードとの通信を待つために停止するのを防ぐことができます。
