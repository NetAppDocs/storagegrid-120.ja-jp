= StorageGRID ADC定足数とは何ですか？
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
廃止後に残る管理ドメインコントローラー（ADC）サービスが少なすぎる場合、サイトの一部のストレージノードを廃止できないことがあります。

一部のストレージノードに搭載されているADCサービスは、グリッドのトポロジー情報を維持し、グリッドに対して構成サービスを提供します。StorageGRIDシステムでは、各拠点において常時、一定数のADCサービスが利用可能であることが求められます。

ストレージノードを削除するとADCのクォーラムが満たされなくなる場合、そのストレージノードを廃止することはできません。廃止措置中にADCのクォーラムを満たすためには、各サイトのストレージノードのうち最低3つがADCサービスに対応している必要があります。サイトにADCサービスを備えたストレージノードが3つ以上ある場合、廃止後もそれらのノードの過半数が利用可能な状態を維持する必要があります。 `((0.5 * _Storage Nodes with ADC_) + 1)`


CAUTION: ソフトウェアベースのメタデータ専用ノードを含むグリッドでストレージノードを廃止する場合は、注意してください。オブジェクトとメタデータの_両方_を保存するように設定されているすべてのノードを廃止すると、グリッドからオブジェクトを保存する機能が削除されます。メタデータ専用ストレージノードの詳細については、link:../primer/what-storage-node-is.html#types-of-storage-nodes["ストレージノードの種類"]を参照してください。

例えば、現在ADCサービスを備えたストレージノードが6台設置されているサイトで、そのうち3台のストレージノードを廃止したいとします。ADCの定足数要件のため、以下の2つの廃止手順を完了する必要があります。

* 最初の廃止手順では、ADCサービスを備えた4つのストレージノードが引き続き利用可能であることを確認する必要があります `((0.5 * 6) + 1)`。つまり、最初に廃止できるストレージノードは2つまでということになります。
* 2番目の廃止手順では、ADCクォーラムに必要なADCサービスが3つだけ残っていればよいので、3番目のストレージノードを削除できます： `((0.5 * 4) + 1)`。


ストレージノードを廃止する必要がある場合は、link:../release-notes/changes-to-grid-management-api.html#new-private-endpoints-for-move-adc["ADCサービスを同じサイト内の別のストレージノードに移動する"]またはlink:../expand/index.html["拡張"]で新しいストレージノードを追加してADCサービスを持つように指定することで、ADCクォーラム要件を満たし続けることができます。その後、クォーラムに影響を与えることなく、既存のストレージノードを廃止できます。
