= テクニカルサポートによるStorageGRIDサイトの復旧方法
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID サイト全体で障害が発生した場合、または複数のストレージノードで障害が発生した場合は、テクニカルサポートにお問い合わせください。テクニカルサポートがお客様の状況を評価し、復旧計画を策定した上で、お客様のビジネス目標を満たし、復旧時間を最適化し、不要なデータ損失を防ぐ方法で、障害が発生したノードまたはサイトを復旧します。


CAUTION: サイト復旧は技術サポートのみが行うことができます。

StorageGRIDシステムは多種多様な障害に対して耐性があり、多くの復旧および保守手順を自身で正常に実行できます。しかし、詳細な手順は個々の状況に特有の要因によって異なるため、単純で汎用的なサイト復旧手順を作成することは困難です。例えば：

* *ビジネス目標*：StorageGRID サイトが完全に失われた場合は、ビジネス目標を達成するための最善の方法を検討する必要があります。たとえば、失われたサイトを元の場所に再構築しますか？失われた StorageGRID サイトを新しい場所に置き換えますか？お客様の状況はそれぞれ異なるため、復旧計画はお客様の優先事項に対応できるように策定する必要があります。
* *障害の正確な性質*：サイト復旧を開始する前に、障害が発生したサイトのノードが損傷を受けていないか、またはストレージノードに復旧可能なオブジェクトが含まれているかどうかを確認してください。有効なデータを含むノードやストレージボリュームを再構築すると、不要なデータ損失が発生する可能性があります。
* *アクティブなILMポリシー*：グリッド内のオブジェクトコピーの数、種類、および場所は、アクティブなILMポリシーによって制御されます。ILMポリシーの具体的な内容は、復旧可能なデータの量だけでなく、復旧に必要な具体的な手法にも影響する場合があります。
+

CAUTION: あるサイトにオブジェクトの唯一のコピーが含まれており、そのサイトが失われた場合、そのオブジェクトも失われます。

* *バケット（またはコンテナ）の一貫性*：バケット（またはコンテナ）に適用される一貫性は、StorageGRID がオブジェクトのメタデータをすべてのノードとサイトに完全にレプリケートしてから、オブジェクトの取り込みが成功したことをクライアントに通知するかどうかに影響します。一貫性値が結果整合性を許可する場合、サイト障害によってオブジェクトのメタデータの一部が失われている可能性があります。これは、復旧可能なデータの量、ひいては復旧手順の詳細に影響を与える可能性があります。
* *最近の変更履歴*：障害発生時にメンテナンス手順が進行中であったかどうか、またはILMポリシーに最近変更が加えられたかどうかによって、復旧手順の詳細が影響を受ける可能性があります。テクニカルサポートは、サイト復旧を開始する前に、グリッドの最近の履歴と現在の状況を評価する必要があります。



CAUTION: サイト復旧は技術サポートのみが行うことができます。

これは、テクニカルサポートが障害が発生したサイトを復旧するために使用するプロセスの一般的な概要です。

. テクニカルサポート：
+
.. 障害の詳細な評価を行います。
.. お客様のビジネス目標の見直しをお手伝いします。
.. お客様の状況に合わせたリカバリプランを作成します。


. プライマリ管理ノードに障害が発生した場合、技術サポートが復旧作業を行います。
. 技術サポートは、以下の手順に従ってすべてのストレージノードを復旧します。
+
.. 必要に応じて、ストレージノードのハードウェアまたは仮想マシンを交換してください。
.. 障害が発生したサイトにオブジェクトのメタデータを復元します。
.. 復旧したストレージノードにオブジェクトデータを復元します。
+

CAUTION: 単一のストレージノードの障害に対する復旧手順を使用すると、データ損失が発生します。

+

NOTE: サイト全体が障害を起こした場合、テクニカルサポートは専用のコマンドを使用して、オブジェクトとオブジェクトのメタデータを正常に復元します。



. 技術サポートが他の障害発生ノードを復旧します。
+
オブジェクトのメタデータとデータが復旧された後、テクニカルサポートは標準的な手順を使用して、障害が発生したゲートウェイノードまたはプライマリ以外の管理ノードを復旧します。
