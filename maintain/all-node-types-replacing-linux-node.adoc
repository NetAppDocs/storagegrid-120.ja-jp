= StorageGRIDのLinuxノードを置き換える
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
障害発生時に、1 台以上の新しい物理ホストまたは仮想ホストをデプロイしたり、既存のホストに Linux を再インストールしたりする必要がある場合は、グリッドノードを復旧する前に、代替ホストをデプロイして構成してください。この手順は、あらゆる種類のグリッドノードにおけるグリッドノード復旧プロセスの 1 つのステップです。

「Linux」とは、Red Hat® Enterprise Linux® (RHEL)、Ubuntu®、またはDebian®のデプロイメントを指します。サポートされているバージョンの一覧については、 https://imt.netapp.com/matrix/#welcome["NetApp Interoperability Matrix Tool（IMT）"^]を参照してください。

この手順は、ソフトウェアベースのストレージノード、プライマリまたは非プライマリの管理ノード、あるいはゲートウェイノードの復旧プロセスにおける1つのステップとしてのみ実行されます。復旧するグリッドノードの種類に関わらず、手順は同じです。

物理または仮想のLinuxホスト上に複数のグリッドノードがホストされている場合、グリッドノードは任意の順序で復旧できます。ただし、プライマリ管理ノードが存在する場合は、まずプライマリ管理ノードを復旧することで、他のグリッドノードが復旧登録のためにプライマリ管理ノードへの接続を試みる際に復旧が停止するのを防ぐことができます。
