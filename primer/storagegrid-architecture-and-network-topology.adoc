= StorageGRID アーキテクチャとネットワークトポロジ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID システムは、1つまたは複数のデータセンターサイトに設置された複数の種類のグリッドノードで構成されています。

link:nodes-and-services.html["グリッドノードの種類"]について学びましょう。

StorageGRID ネットワークトポロジー、要件、およびグリッド通信の詳細については、link:../network/index.html["ネットワーク構築ガイドライン"]を参照してください。



[[deployment-topologies]]
== 展開トポロジー

StorageGRID システムは、単一のデータセンターサイト、または複数のデータセンターサイトに展開できます。1回の展開で設定できるサイトの最大数は16です。



[[single-site]]
=== 単一サイト

単一サイトでの展開では、StorageGRID システムのインフラストラクチャと運用は一元管理されます。

image:data_center_site_single.png["単一データセンターサイト"]



[[multiple-sites]]
=== 複数の拠点

複数のサイトを含む構成では、異なるタイプと数の StorageGRID リソースを各サイトにインストールできます。たとえば、あるデータセンターでは、別のデータセンターよりも多くのストレージが必要になる場合があります。

サイトは、地震断層線や氾濫原など、異なる障害ドメインにわたる地理的に異なる場所に位置していることが多いです。データ共有とディザスタリカバリは、データを他のサイトに自動的に配信することによって実現されます。

image:data_center_sites_multiple.png["複数のデータセンターサイト"]

単一のデータセンター内に複数の論理サイトを設けることで、分散レプリケーションとイレイジャー コーディングを活用して可用性と回復力を高めることができます。



[[grid-node-redundancy]]
=== グリッドノードの冗長性

単一サイトまたは複数サイトの展開において、冗長性を確保するために、管理ノードまたはゲートウェイノードを複数含めることができます。例えば、1つのサイトに複数の管理ノードをインストールしたり、複数のサイトにまたがってインストールしたりすることができます。ただし、各 StorageGRID システムに配置できるプライマリ管理ノードは1つのみです。



[[system-architecture]]
== システムアーキテクチャ

この図は、グリッドノードが StorageGRID システム内でどのように配置されているかを示しています。

image:grid_nodes_and_components.png["周囲のテキストで説明されている図"]

S3クライアントは、StorageGRID でオブジェクトを保存および取得します。他のクライアントは、電子メール通知の送信、StorageGRID 管理インターフェイスへのアクセス、および必要に応じて監査共有へのアクセスに使用されます。

S3クライアントは、ゲートウェイノードまたは管理ノードに接続して、ストレージノードへのロード バランシング インターフェイスを使用できます。あるいは、S3クライアントはHTTPSを使用してストレージノードに直接接続することもできます。

オブジェクトは、StorageGRID 内のソフトウェアまたはハードウェアベースのストレージノード、あるいは外部の S3 バケットまたは Azure Blob ストレージコンテナで構成されるクラウドストレージプールに保存できます。
