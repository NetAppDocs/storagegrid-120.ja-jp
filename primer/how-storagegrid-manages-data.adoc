= StorageGRIDオブジェクトとは
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
オブジェクトストレージでは、ストレージの単位はファイルやブロックではなく、オブジェクトです。ファイルシステムやブロックストレージのようなツリー状の階層構造とは異なり、オブジェクトストレージはデータをフラットで非構造的なレイアウトで整理します。

オブジェクトストレージは、データの物理的な場所と、そのデータを保存および取得するために使用される方法を分離します。

オブジェクトベースのストレージシステムにおける各オブジェクトは、オブジェクトデータとオブジェクトメタデータの2つの部分から構成されます。

image:object_conceptual_drawing.png["オブジェクト"]



[[what-is-object-data]]
== オブジェクトデータとは何ですか？

オブジェクトデータは、写真、動画、医療記録など、あらゆるものが対象となります。



[[what-is-object-metadata]]
== オブジェクトメタデータとは何ですか？

オブジェクトのメタデータとは、オブジェクトを説明するあらゆる情報のことです。StorageGRID は、オブジェクトのメタデータを使用して、グリッド全体にわたるすべてのオブジェクトの位置を追跡し、各オブジェクトのライフサイクルを長期にわたって管理します。

オブジェクトのメタデータには、次のような情報が含まれます。

* システムメタデータには、各オブジェクトの一意のID（UUID）、オブジェクト名、S3バケット名、テナントアカウント名またはID、オブジェクトの論理サイズ、オブジェクトが最初に作成された日時、およびオブジェクトが最後に変更された日時が含まれます。
* 各オブジェクトコピーまたはイレイジャー コーディング フラグメントの現在の保存場所。
* オブジェクトに関連付けられたユーザーメタデータ。


オブジェクトのメタデータはカスタマイズおよび拡張が可能であり、アプリケーションが柔軟に利用できます。

StorageGRID がオブジェクトのメタデータを保存する方法と場所の詳細については、link:../admin/managing-object-metadata-storage.html["オブジェクトメタデータストレージの管理"]を参照してください。



[[how-is-object-data-protected]]
== オブジェクトデータはどのように保護されますか？

StorageGRID システムは、オブジェクトデータの損失を防ぐための 2 つのメカニズムを提供します：レプリケーションとイレイジャー コーディング。



[[replication]]
=== レプリケーション

StorageGRID が、レプリケートされたコピーを作成するように設定された情報ライフサイクル管理（ILM）ルールにオブジェクトを照合すると、システムはオブジェクトデータの正確なコピーを作成し、ストレージノードまたはクラウドストレージプールに保存します。ILM ルールは、作成されるコピーの数、コピーの保管場所、およびシステムによる保持期間を規定します。たとえば、ストレージノードの損失によってコピーが失われた場合でも、StorageGRID システム内の別の場所にオブジェクトのコピーが存在すれば、オブジェクトは引き続き利用可能です。

次の例では、「2 つのコピーを作成」ルールにより、各オブジェクトの複製コピーが 2 つ、3 つの Storage Node を含むストレージプールに配置されるように指定されています。

image:ilm_replication_make_2_copies.png["2 部コピーを作成するルール"]



[[erasure-coding]]
=== イレイジャー コーディング

StorageGRID がオブジェクトをイレイジャー コーディング コピーを作成するように構成された ILM ルールに照合すると、オブジェクト データをデータ フラグメントに分割し、追加のパリティ フラグメントを計算して、各フラグメントを異なる Storage Node に保存します。オブジェクトにアクセスすると、保存されているフラグメントを使用してオブジェクトが再構築されます。データまたはパリティ フラグメントが破損または失われた場合、イレイジャー コーディング アルゴリズムは、残りのデータ フラグメントとパリティ フラグメントのサブセットを使用して、そのフラグメントを再作成できます。ILM ルールとイレイジャー コーディング プロファイルによって、使用されるイレイジャー コーディング方式が決定されます。

次の例は、オブジェクトのデータに対するイレイジャー コーディングの使用方法を示しています。この例では、ILM ルールは 4+2 のイレイジャー コーディング方式を使用しています。各オブジェクトは 4 つの等しいデータ フラグメントに分割され、オブジェクト データから 2 つのパリティ フラグメントが計算されます。6 つのフラグメントはそれぞれ、3 つのデータセンターにまたがる異なる Storage Node に保存され、ノード障害やサイト損失に対するデータ保護を提供します。

image:ec_three_sites_4_plus_2.png["イレイジャー コーディング 3サイト 4+2"]
