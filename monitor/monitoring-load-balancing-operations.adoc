= StorageGRID でロード バランシング操作を監視
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
クライアント接続を管理するために StorageGRID でロード バランサーを使用している場合は、システムの初期設定後、および設定変更や拡張を行った後に、ロード バランシングの動作を監視する必要があります。

.タスク概要
管理ノードまたはゲートウェイノード上のロード バランシング サービス、あるいは外部のサードパーティ製ロードバランサーを使用して、クライアントからのリクエストを複数のストレージノードに分散させることができます。

ロード バランシングを設定したら、オブジェクトの取り込みと取得操作がストレージノード全体に均等に分散されていることを確認してください。均等に分散されたリクエストにより、StorageGRID は負荷がかかった状態でもクライアントからのリクエストに迅速に対応し、クライアントのパフォーマンス維持に貢献できます。

ゲートウェイノードまたは管理ノードの高可用性（HA）グループをアクティブ/バックアップモードで構成した場合、グループ内のノードのうち1つだけがクライアント要求をアクティブに分散します。

詳細については、link:../admin/configuring-client-connections.html["S3クライアント接続の設定"]を参照してください。

.手順
. S3クライアントがロード バランシング サービスを使用して接続する場合、管理ノードまたはゲートウェイノードが想定どおりにネットワーク トラフィックを分散していることを確認してください。
+
.. * Nodes * を選択します。
.. ゲートウェイノードまたは管理ノードを選択してください。
.. 「概要」タブで、ノードインターフェイスがHAグループに属しているかどうか、およびノードインターフェイスがプライマリの役割を持っているかどうかを確認します。
+
プライマリの役割を持つノードと、HAグループに属していないノードは、クライアントへのリクエストを積極的に分散する必要があります。

.. クライアント要求をアクティブに分散させる必要がある各ノードについて、link:viewing-load-balancer-tab.html["ロード バランシング タブ"]を選択します。
.. 過去1週間の ロード バランシング リクエスト ネットワーク トラフィック のグラフを確認し、ノードがリクエストを積極的に分散していることを確認してください。
+
アクティブ/バックアップ構成のHAグループ内のノードは、時折バックアップの役割を担うことがあります。その間、ノードはクライアントからのリクエストを配信しません。

.. ノードのオブジェクト スループットを確認するには、過去1週間の「ロード バランサーの着信リクエスト レート」のグラフを確認してください。
.. StorageGRID システムの管理ノードまたはゲートウェイノードごとに、これらの手順を繰り返します。
.. 必要に応じて、トラフィック分類ポリシーを使用して、ロード バランシング サービスによって処理されるネットワーク トラフィックのより詳細な分析を表示できます。


. これらのリクエストがストレージノードに均等に分散されていることを確認してください。
+
.. *_ストレージノード_* > *LDR* > *HTTP* を選択します。
.. 現在確立されている着信セッションの数を確認してください。
.. グリッド内の各ストレージノードに対して、この手順を繰り返します。
+
セッション数は、すべてのストレージノードでほぼ均等である必要があります。
