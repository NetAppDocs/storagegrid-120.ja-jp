= StorageGRID ログファイル
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID は、イベント、診断メッセージ、およびエラー状態を記録するために使用されるログを提供します。トラブルシューティングを支援するため、ログファイルを収集してテクニカルサポートに転送するよう求められる場合があります。

ログは以下のように分類されます：

* link:storagegrid-software-logs.html["StorageGRID ソフトウェアログ"]
* link:deployment-and-maintenance-logs.html["展開および保守ログ"]
* link:about-bycast-log.html["bycast.logについて"]



NOTE: 各ログタイプに関する詳細は参考情報としてのみ提供されています。これらのログは、テクニカルサポートによる高度なトラブルシューティングを目的としています。監査ログやアプリケーションログファイルを用いて問題履歴を再構築する高度な手法は、本手順書の範囲外です。



[[access-the-logs]]
== ログにアクセスする

ログにアクセスするには、link:collecting-log-files-and-system-data.html["ログファイルとシステムデータを収集する"] 1つまたは複数のノードから、単一のログファイルアーカイブとして出力します。または、各グリッドノードの個別のログファイルには、次のようにアクセスできます。

.手順
. 次のコマンドを入力します： `ssh admin@grid_node_IP`
.  `Passwords.txt`ファイルに記載されているパスワードを入力してください。
. 以下のコマンドを入力して root に切り替えます： `su -`
.  `Passwords.txt`ファイルに記載されているパスワードを入力してください。




[[export-logs-to-the-syslog-server]]
== ログを syslog サーバにエクスポートする

ログを syslog サーバーにエクスポートすることで、以下の機能が提供されます：

* S3リクエストに加え、Grid ManagerおよびTenant Managerのすべてのリクエストのリストを受け取ります。
* 監査ログ記録方法によるパフォーマンスへの影響なしに、エラーを返す S3 リクエストをより詳細に把握できます。
* 解析しやすいHTTPレイヤーのリクエストとエラーコードへのアクセス。
* ロードバランサーのトラフィック分類器によってブロックされたリクエストへの可視性が向上しました。


ログをエクスポートするには、link:../monitor/configure-log-management.html["ログ管理と外部 syslog サーバの設定"]を参照してください。
