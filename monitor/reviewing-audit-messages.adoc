= StorageGRID 監査メッセージを確認
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
監査メッセージは、StorageGRID システムの詳細な動作をより深く理解するのに役立ちます。監査ログは、問題のトラブルシューティングやパフォーマンスの評価に利用できます。

通常のシステム動作中、すべての StorageGRID サービスは以下のように監査メッセージを生成します。

* システム監査メッセージは、監査システム自体、グリッドノードの状態、システム全体のタスクアクティビティ、およびサービスバックアップ操作に関連しています。
* オブジェクトストレージ監査メッセージは、StorageGRID 内のオブジェクトのストレージと管理に関連しており、オブジェクトの保存と取得、グリッドノード間の転送、および検証が含まれます。
* S3クライアントアプリケーションがオブジェクトの作成、変更、または取得を要求すると、クライアントの読み取りおよび書き込み監査メッセージがログに記録されます。
* 管理監査メッセージは、管理APIへのユーザーリクエストをログに記録します。


各管理ノードは、監査メッセージをテキストファイルに保存します。監査共有フォルダには、アクティブなファイル（audit.log）と、過去の日付の圧縮された監査ログが含まれています。グリッド内の各ノードは、そのノードで生成された監査情報のコピーも保存します。

管理ノードのコマンドラインから監査ログファイルに直接アクセスできます。

StorageGRID はデフォルトで監査情報を送信できますが、送信先を変更することもできます。

* StorageGRID はデフォルトで、ローカルノードの監査先が設定されます。
* Grid ManagerおよびTenant Managerの監査ログエントリは、ストレージノードに送信される場合があります。
* オプションで、監査ログの送信先を変更し、監査情報を外部 syslog サーバーに送信できます。外部 syslog サーバーが設定されている場合でも、監査レコードのローカルログは引き続き生成および保存されます。
* link:../monitor/configure-log-management.html["ログ管理の設定について"]。


監査ログファイル、監査メッセージのフォーマット、監査メッセージの種類、および監査メッセージを分析するために使用できるツールの詳細については、link:../audit/index.html["監査ログを確認する"]を参照してください。
