= StorageGRIDでオブジェクト検証操作を監視する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID システムは、ストレージノード上のオブジェクトデータの整合性を検証し、破損したオブジェクトと欠落したオブジェクトの両方をチェックできます。

.開始する前に
* link:../admin/web-browser-requirements.html["対応ウェブブラウザ"] を使用して Grid Manager にサインインしています。
* あなたはlink:../admin/admin-group-permissions.html["メンテナンス権限またはルートアクセス権限"]があります。


.タスク概要
2つのlink:../troubleshoot/verifying-object-integrity.html["検証プロセス"]が連携してデータの整合性を確保します：

* *バックグラウンド検証*は自動的に実行され、オブジェクトデータの正確性を継続的にチェックします。
+
バックグラウンド検証では、すべてのストレージノードを自動的かつ継続的にチェックし、レプリケートおよびイレイジャー コーディングされたオブジェクトデータの破損したコピーが存在するかどうかを判断します。問題が見つかった場合、StorageGRID システムは、システム内の別の場所に保存されているコピーから、破損したオブジェクトデータを自動的に置き換えようとします。クラウドストレージプール内のオブジェクトに対しては、バックグラウンド検証は実行されません。

+

NOTE: *未確認の破損オブジェクトが検出されました* アラートは、システムが自動的に修正できない破損オブジェクトを検出した場合に発生します。

* *オブジェクト存在チェック*は、オブジェクトデータの存在（ただし、正確性ではない）をより迅速に検証するために、ユーザーがトリガーできます。
+
オブジェクト存在チェックは、ストレージノード上に想定されるすべての複製オブジェクトおよびイレイジャー コーディングフラグメントが存在するかどうかを検証します。オブジェクト存在チェックは、特に最近のハードウェアの問題がデータの整合性に影響を与えた可能性がある場合に、ストレージデバイスの整合性を検証する方法を提供します。



バックグラウンド検証とオブジェクト存在チェックの結果を定期的に確認する必要があります。オブジェクトデータの破損や欠落が発生した場合は、直ちに調査を行い、根本原因を特定してください。

.手順
. バックグラウンド検証の結果を確認します。
+
.. 「ノード」>「_ストレージノード_」>「オブジェクト」を選択します。
.. 検証結果を確認してください：
+
*** 複製されたオブジェクトデータの検証を確認するには、「検証」セクションの属性を参照してください。
+
image:nodes_storage_node_object_verification.png["ノード > ストレージノード > オブジェクト > 検証"]

*** イレイジャー コーディング フラグメントの検証を確認するには、*_Storage Node_* > *ILM* を選択し、イレイジャー コーディング検証セクションの属性を確認してください。
+
image:nodes_storage_node_ilm_ec_verification.png["ノード > ストレージノード > ILM > EC検証"]

+
属性名の横にある疑問符image:icon_nms_question.png["疑問符"]を選択すると、ヘルプテキストが表示されます。





. オブジェクト存在チェックジョブの結果を確認します。
+
.. *メンテナンス* ＞ *オブジェクト存在チェック* ＞ *ジョブ履歴* を選択します。
.. 「検出された欠落オブジェクトコピー数」列をスキャンしてください。ジョブの結果、オブジェクトのコピーが100個以上欠落し、*オブジェクトが失われた可能性があります*というアラートがトリガーされた場合は、テクニカルサポートにお問い合わせください。
+
image:oec_job_history.png["オブジェクト存在チェックのジョブ履歴"]
