= StorageGRIDで情報ライフサイクル管理を監視
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
情報ライフサイクル管理（ILM）システムは、グリッド上に保存されているすべてのオブジェクトのデータ管理機能を提供します。グリッドが現在の負荷に対応できるかどうか、あるいは追加のリソースが必要かどうかを把握するために、ILM の運用状況を監視する必要があります。

.タスク概要
StorageGRID システムは、有効な ILM ポリシーを適用することによってオブジェクトを管理します。ILM ポリシーおよび関連する ILM ルールは、作成されるコピーの数、作成されるコピーの種類、コピーの保管場所、および各コピーの保管期間を規定します。

オブジェクトの取り込みやその他のオブジェクト関連のアクティビティが、StorageGRID が ILM を評価できる速度を超えると、システムは ILM 配置指示をほぼリアルタイムで実行できないオブジェクトをキューに格納することになります。StorageGRID がクライアントの処理に追いついているかどうかを監視する必要があります。



[[use-grid-manager-dashboard-tab]]
== グリッドマネージャーのダッシュボードタブを使用する

.手順
Grid ManagerダッシュボードのILMタブを使用して、ILM処理を監視します。

. Grid Manager にサインインします。
. ダッシュボードから「ILM」タブを選択し、「ILM キュー（オブジェクト）」カードと「ILM 評価率」カードの値を確認してください。
+
ダッシュボード上の ILM キュー（オブジェクト）カードに一時的な急増が見られることがありますが、これは想定内の動作です。ただし、キューが増加し続け、減少しない場合は、グリッドが効率的に動作するためにより多くのリソースが必要です。つまり、Storage Node を増やすか、ILM ポリシーによってオブジェクトがリモートの場所に配置される場合は、ネットワーク帯域幅を増やす必要があります。





[[use-the-nodes-page]]
== ノードページの使用

.手順
さらに、*ノード*ページを使用して ILM キューを調査します。


NOTE: *ノード*ページのグラフは、将来の StorageGRID リリースで対応するダッシュボードカードに置き換えられる予定です。

. * Nodes * を選択します。
. *_グリッド名_* > *ILM* を選択します。
. ILMキューグラフ上にカーソルを合わせると、特定の時点における以下の属性の値を確認できます。
+
** *キューに入れられたオブジェクト（クライアント操作による）*：クライアント操作（例：取り込み）のために情報ライフサイクル管理（ILM）評価を待機しているオブジェクトの総数。
** *キューに入れられたオブジェクト（すべての操作から）*：ILM評価を待機しているオブジェクトの総数。
** *スキャンレート（オブジェクト/秒）*：グリッド内のオブジェクトがスキャンされ、ILM 用にキューに追加されるレート。
** *評価レート（オブジェクト/秒）*：グリッド内でオブジェクトがILMポリシーに対して評価されている現在のレート。


+

NOTE: ILMキューセクションは、グリッド専用です。この情報は、サイトまたはストレージノードのILMタブには表示されません。

. ILMキューのセクションで、以下の属性を確認してください。
+
** *スキャン期間 - 推定*：すべてのオブジェクトの完全な ILM スキャンを完了するまでの推定時間。
+

NOTE: フルスキャンを実行しても、ILMがすべてのオブジェクトに適用されたとは限りません。

** *修復試行回数*：複製データに対して試行されたオブジェクト修復操作の総数。このカウントは、ストレージノードが高リスクオブジェクトの修復を試みるたびに増加します。グリッドが混雑した場合、リスクの高い ILM 修復が優先されます。
+
修復後にレプリケーションが失敗した場合、同じオブジェクトの修復が再び実行される可能性があります。+ これらの属性は、ストレージノードボリュームの復旧状況を監視する際に役立ちます。修復試行回数の増加が止まり、フルスキャンが完了した場合、修復はおそらく完了しています。



. または、 `storagegrid_ilm_scan_period_estimated_minutes`および `storagegrid_ilm_repairs_attempted`のPrometheusクエリを送信します。
