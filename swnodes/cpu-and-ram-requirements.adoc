= StorageGRIDのCPUとRAMの要件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID ソフトウェアをインストールする前に、ハードウェアを検証および構成して、StorageGRID システムをサポートできる状態にしてください。

各 StorageGRID ノードには、以下の最小リソースが必要です：

* CPUコア数：ノードあたり8個
* RAM：利用可能なRAMの総量と、システム上で実行されているStorageGRID以外のソフトウェアの量によって異なります。
+
** 一般的に、ノードあたり最低 24 GB、システム全体の RAM より 2～16 GB 少ない容量が必要です。
** テナントごとに最低 64 GB が必要です（各テナントのバケット数は約 5,000 個を想定）。




ソフトウェアベースのメタデータ専用ノードリソースは、既存のストレージノードリソースと一致している必要があります。例：

* 既存の StorageGRID サイトで SG6000 または SG6100 アプライアンスを使用している場合、ソフトウェアベースのメタデータ専用ノードは以下の最小要件を満たす必要があります：
+
** 128GBのRAM
** 8コアCPU
** Cassandraデータベース用に8 TB SSDまたは同等のストレージ（rangedb/0）


* 既存の StorageGRID サイトで 24 GB RAM、8 コア CPU、3 TB または 4 TB のメタデータストレージを備えた仮想ストレージノードを使用している場合、ソフトウェアベースのメタデータ専用ノードも同様のリソース（24 GB RAM、8 コア CPU、4 TB のメタデータストレージ（rangedb/0））を使用する必要があります。


新しい StorageGRID サイトを追加する場合、新しいサイトの合計メタデータ容量は、少なくとも既存の StorageGRID サイトと同等である必要があり、新しいサイトのリソースは既存の StorageGRID サイトのストレージノードと一致する必要があります。


NOTE: 「Linux」とは、RHEL、Ubuntu、またはDebianのいずれかの環境を指します。サポートされているバージョンの一覧については、 https://imt.netapp.com/matrix/#welcome["NetApp Interoperability Matrix Tool（IMT）"^]を参照してください。

[role="tabbed-block"]
====
.Linux
--
各物理ホストまたは仮想ホスト上で実行する予定の StorageGRID ノード数が、利用可能な CPU コア数または物理 RAM 容量を超えないようにしてください。ホストが StorageGRID の実行専用でない場合（推奨しません）、他のアプリケーションのリソース要件を必ず考慮してください。

--
.VMware
--
VMwareは仮想マシンごとに1つのノードをサポートします。StorageGRIDノードが使用可能な物理RAMを超えないようにしてください。各仮想マシンはStorageGRIDの実行専用でなければなりません。

--
====

CAUTION: CPUとメモリの使用状況を定期的に監視し、これらのリソースが引き続き作業負荷に対応できることを確認してください。例えば、仮想ストレージノードのRAMとCPUの割り当てを2倍にすると、StorageGRIDアプライアンスノードに提供されるリソースと同様のリソースが提供されます。さらに、ノードあたりのメタデータ量が500 GBを超える場合は、ノードあたりのRAMを48 GB以上に増やすことを検討してください。オブジェクトメタデータストレージの管理、メタデータ予約領域設定の増加、CPUとメモリ使用量の監視に関する情報については、link:../admin/index.html["管理する"]、link:../monitor/index.html["監視"]、およびlink:../upgrade/index.html["upgrading"] StorageGRIDの手順を参照してください。

基盤となる物理ホストでハイパースレッディングが有効になっている場合、ノードごとに8つの仮想コア（4つの物理コア）を提供できます。基盤となる物理ホストでハイパースレッディングが有効になっていない場合は、ノードごとに8つの物理コアを用意する必要があります。

仮想マシンをホストとして使用していて、VMのサイズと数を制御できる場合は、StorageGRIDノードごとに1つのVMを使用し、それに応じてVMのサイズを設定してください。

（RHEL、Debian、Ubuntu のみ）本番環境でのデプロイメントでは、同じ物理ストレージハードウェアまたは仮想ホスト上で複数のストレージノードを実行しないでください。単一の StorageGRID デプロイメントにおける各ストレージノードは、独立した障害ドメイン内に配置する必要があります。単一のハードウェア障害が単一のストレージノードにのみ影響するように構成することで、オブジェクトデータの耐久性と可用性を最大限に高めることができます。

link:storage-and-performance-requirements.html["ストレージとパフォーマンスの要件"]も参照してください。
