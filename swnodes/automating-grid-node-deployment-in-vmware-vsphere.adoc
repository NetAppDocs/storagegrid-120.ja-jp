= StorageGRIDでVMware vSphereを使用してグリッドノードの導入を自動化
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
VMware OVF Tool を使用すると、グリッドノードの展開を自動化できます。StorageGRID の設定を自動化することもできます。



[[automate-grid-node-deployment]]
== グリッドノードの展開を自動化する

VMware OVF Tool を使用して、グリッドノードの展開を自動化します。

.開始する前に
* Bash 3.2以降がインストールされたLinux/Unixシステムにアクセスできる環境が必要です。
* VMware vSphereとvCenterをお持ちの場合
* VMware OVF Toolがインストールされ、正しく設定されています。
* OVF Tool を使用して VMware vSphere にアクセスするためのユーザー名とパスワードを把握している
* OVFファイルから仮想マシンをデプロイして電源をオンにするのに十分な権限、および仮想マシンに接続する追加ボリュームを作成する権限をお持ちです。詳細については、 `ovftool`ドキュメントを参照してください。
* StorageGRID 仮想マシンをデプロイする vSphere 内の場所の仮想インフラ（VI）URL を把握しておく必要があります。この URL は通常、vApp またはリソースプールです。例： `vi://vcenter.example.com/vi/sgws`
+

NOTE: VMware `ovftool`ユーティリティを使用してこの値を確認できます（詳細については `ovftool`ドキュメントを参照してください）。

+

NOTE: 展開先がvAppの場合、仮想マシンは初回起動時には自動的に起動しないため、手動で電源を入れる必要があります。

* デプロイメント構成ファイルに必要な情報をすべて収集しました。詳細については、link:collecting-information-about-your-deployment-environment.html["デプロイ環境に関する情報を収集する"]を参照してください。
* StorageGRID の VMware インストールアーカイブから、以下のファイルにアクセスできます：


[cols="1a,1a"]
|===
| ファイル名 | 説明 


| NetApp-SG-version-SHA.vmdk  a| 
グリッドノード仮想マシンを作成するためのテンプレートとして使用される仮想マシンディスクファイル。

*注:* このファイルは、 `.ovf`および `.mf`ファイルと同じフォルダに配置する必要があります。



| vsphere-primary-admin.ovf vsphere-primary-admin.mf  a| 
Open Virtualization Formatテンプレートファイル(`.ovf`）とマニフェストファイル(`.mf`）は、プライマリ管理ノードをデプロイするためのものです。



| vsphere-non-primary-admin.ovf vsphere-non-primary-admin.mf  a| 
テンプレートファイル(`.ovf`）とマニフェストファイル(`.mf`）は、プライマリ以外の管理ノードをデプロイするためのものです。



| vsphere-gateway.ovf vsphere-gateway.mf  a| 
テンプレートファイル(`.ovf`）とマニフェストファイル(`.mf`）は、Gateway Nodes をデプロイするためのものです。



| vsphere-storage.ovf vsphere-storage.mf  a| 
テンプレートファイル(`.ovf`）とマニフェストファイル(`.mf`）は、仮想マシンベースのストレージノードをデプロイするためのものです。



| deploy-vsphere-ovftool.sh  a| 
仮想グリッドノードのデプロイを自動化するために使用されるBashシェルスクリプト。



| deploy-vsphere-ovftool-sample.ini  a| 
 `deploy-vsphere-ovftool.sh`スクリプトで使用するためのサンプル設定ファイル。

|===


[[define-the-configuration-file-for-your-deployment]]
=== デプロイメントの構成ファイルを定義します

StorageGRID の仮想グリッドノードをデプロイするために必要な情報を設定ファイルに指定します。この設定ファイルは `deploy-vsphere-ovftool.sh` Bash スクリプトで使用されます。サンプル設定ファイルを修正すれば、ファイルを一から作成する必要はありません。

.手順
. サンプル設定ファイルのコピーを作成します（(`deploy-vsphere-ovftool.sample.ini`）。新しいファイルを `deploy-vsphere-ovftool.ini`として、 `deploy-vsphere-ovftool.sh`と同じディレクトリに保存します。
. 開く `deploy-vsphere-ovftool.ini`。
. VMware仮想グリッドノードをデプロイするために必要なすべての情報を入力してください。
+
詳細については、<<configuration-file-settings,設定ファイルの設定>>を参照してください。

. 必要な情報をすべて入力し、確認したら、ファイルを保存して閉じます。




[[configuration-file-settings]]
=== 設定ファイルの設定

 `deploy-vsphere-ovftool.ini`設定ファイルには、仮想グリッドノードをデプロイするために必要な設定が含まれています。

設定ファイルには、まずグローバルパラメータが一覧表示され、次にノード名で定義されたセクションごとにノード固有のパラメータが一覧表示されます。ファイルを使用する場合：

* グローバルパラメータは、すべてのグリッドノードに適用されます。
* ノード固有のパラメータは、グローバルパラメータを上書きします。




==== グローバルパラメータ

グローバルパラメータは、個々のセクションの設定によって上書きされない限り、すべてのグリッドノードに適用されます。複数のノードに適用されるパラメータはグローバルパラメータセクションに配置し、必要に応じて個々のノードのセクションでこれらの設定を上書きしてください。

* *OVFTOOL_ARGUMENTS*: OVFTOOL_ARGUMENTSはグローバル設定として指定することも、特定のノードに個別に引数を適用することもできます。例：
+
[listing, subs="specialcharacters,quotes"]
----
OVFTOOL_ARGUMENTS = --powerOn --noSSLVerify --diskMode=eagerZeroedThick --datastore='_datastore_name_'
----
+
 `--powerOffTarget`および `--overwrite`オプションを使用して、既存の仮想マシンをシャットダウンして置き換えることができます。

+

CAUTION: ノードを異なるデータストアにデプロイし、グローバルではなく各ノードに対して OVFTOOL_ARGUMENTS を指定する必要があります。

* *出典*：StorageGRID 仮想マシンテンプレート(`.vmdk`）ファイルと `.ovf`および `.mf`個々のグリッドノードに対応するファイルへのパス。デフォルトは現在のディレクトリです。
+
[listing, subs="specialcharacters,quotes"]
----
SOURCE = /downloads/StorageGRID-Webscale-_version_/vsphere
----
* *TARGET*: StorageGRID がデプロイされる場所の VMware vSphere 仮想インフラ（vi）URL。例：
+
[listing]
----
TARGET = vi://vcenter.example.com/vm/sgws
----
* *GRID_NETWORK_CONFIG*：IPアドレスを取得するために使用される方法。STATIC または DHCP のいずれか。デフォルトは STATIC です。すべてのノード、またはほとんどのノードが同じ方法で IP アドレスを取得する場合は、ここでその方法を指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
GRID_NETWORK_CONFIG = STATIC
----
* *GRID_NETWORK_TARGET*：グリッドネットワークに使用する既存の VMware ネットワークの名前。すべてのノード、またはほとんどのノードが同じネットワーク名を使用している場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
GRID_NETWORK_TARGET = SG Admin Network
----
* *GRID_NETWORK_MASK*：グリッドネットワークのネットワークマスク。すべてのノード、またはほとんどのノードが同じネットワークマスクを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
GRID_NETWORK_MASK = 255.255.255.0
----
* *GRID_NETWORK_GATEWAY*：グリッドネットワークのネットワークゲートウェイ。すべてのノード、またはほとんどのノードが同じネットワークゲートウェイを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
GRID_NETWORK_GATEWAY = 10.1.0.1
----
* *GRID_NETWORK_MTU*：オプション。グリッドネットワークにおける最大伝送単位（MTU）。指定する場合、値は1280から9216の間である必要があります。例：
+
[listing]
----
GRID_NETWORK_MTU = 9000
----
+
省略した場合、1400が使用されます。

+
ジャンボフレームを使用する場合は、MTU をジャンボフレームに適した値（9000 など）に設定してください。それ以外の場合は、デフォルト値を維持してください。

+

NOTE: ネットワークの MTU 値は、ノードが接続されている vSphere の仮想スイッチ ポートに設定されている値と一致する必要があります。一致していない場合、ネットワークのパフォーマンス低下やパケットロスが発生する可能性があります。

+

NOTE: 最適なネットワークパフォーマンスを実現するには、すべてのノードのグリッドネットワークインターフェースに同様のMTU値を設定する必要があります。個々のノードにおけるグリッドネットワークのMTU設定に大きな差異がある場合、*グリッドネットワークMTU不一致*アラートがトリガーされます。MTU値は、すべてのネットワークタイプで同じである必要はありません。

* *ADMIN_NETWORK_CONFIG*：IPアドレスを取得するために使用される方法。DISABLED、STATIC、またはDHCPのいずれか。デフォルトはDISABLEDです。すべてのノード、またはほとんどのノードが同じ方法でIPアドレスを取得する場合は、ここでその方法を指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_CONFIG = STATIC
----
* *ADMIN_NETWORK_TARGET*：管理ネットワークに使用する既存の VMware ネットワークの名前。管理ネットワークが無効になっていない限り、この設定は必須です。すべてのノード、またはほとんどのノードが同じネットワーク名を使用している場合は、ここで指定できます。グリッドネットワークとは異なり、すべてのノードが同じ管理ネットワークに接続されている必要はありません。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_TARGET = SG Admin Network
----
* *ADMIN_NETWORK_MASK*：管理ネットワークのネットワークマスク。静的IPアドレスを使用する場合は、この設定が必要です。すべてのノード、またはほとんどのノードが同じネットワークマスクを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_MASK = 255.255.255.0
----
* *ADMIN_NETWORK_GATEWAY*：管理ネットワークのネットワークゲートウェイ。静的IPアドレスを使用し、ADMIN_NETWORK_ESL設定で外部サブネットを指定する場合は、この設定が必要です。（つまり、ADMIN_NETWORK_ESLが空の場合は不要です。）すべてのノード、またはほとんどのノードが同じネットワークゲートウェイを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_GATEWAY = 10.3.0.1
----
* *ADMIN_NETWORK_ESL*：管理ネットワークの外部サブネットリスト（ルート）。CIDRルート宛先をカンマ区切りで指定します。すべてのノード、またはほとんどのノードが同じ外部サブネットリストを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_ESL = 172.16.0.0/21,172.17.0.0/21
----
* *ADMIN_NETWORK_MTU*: オプション。管理ネットワークにおける最大伝送単位（MTU）。ADMIN_NETWORK_CONFIG = DHCP の場合は指定しないでください。指定する場合、値は 1280 から 9216 の間である必要があります。省略した場合、1400 が使用されます。ジャンボフレームを使用する場合は、MTU をジャンボフレームに適した値（9000 など）に設定してください。それ以外の場合は、デフォルト値を維持してください。管理ネットワークにおいて、すべてのノードまたはほとんどのノードが同じ MTU を使用する場合は、ここで指定できます。その後、1 つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
ADMIN_NETWORK_MTU = 8192
----
* *CLIENT_NETWORK_CONFIG*: IPアドレスを取得するために使用される方法。DISABLED、STATIC、またはDHCPのいずれか。デフォルトはDISABLEDです。全てのノード、またはほとんどのノードが同じ方法でIPアドレスを取得する場合は、ここでその方法を指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例えば：
+
[listing]
----
CLIENT_NETWORK_CONFIG = STATIC
----
* *CLIENT_NETWORK_TARGET*：クライアント ネットワークに使用する既存の VMware ネットワークの名前。クライアントネットワークが無効になっていない限り、この設定は必須です。すべてのノード、またはほとんどのノードが同じネットワーク名を使用している場合は、ここで指定できます。グリッドネットワークとは異なり、すべてのノードが同じクライアントネットワークに接続されている必要はありません。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
CLIENT_NETWORK_TARGET = SG Client Network
----
* *CLIENT_NETWORK_MASK*：クライアントネットワークのネットワークマスク。静的IPアドレスを使用する場合は、この設定が必要です。すべてのノード、またはほとんどのノードが同じネットワークマスクを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
CLIENT_NETWORK_MASK = 255.255.255.0
----
* *CLIENT_NETWORK_GATEWAY*：クライアントネットワークのネットワークゲートウェイ。静的IPアドレスを使用する場合は、この設定が必要です。すべてのノード、またはほとんどのノードが同じネットワークゲートウェイを使用する場合は、ここで指定できます。その後、1つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
CLIENT_NETWORK_GATEWAY = 10.4.0.1
----
* *CLIENT_NETWORK_MTU*：オプション。クライアントネットワークにおける最大伝送単位（MTU）。CLIENT_NETWORK_CONFIG = DHCP の場合は指定しないでください。指定する場合、値は 1280 から 9216 の間である必要があります。省略した場合、1400 が使用されます。ジャンボフレームを使用する場合は、MTU をジャンボフレームに適した値（9000 など）に設定してください。それ以外の場合は、デフォルト値を維持してください。クライアントネットワークで全てのノードまたはほとんどのノードが同じ MTU を使用する場合は、ここで指定できます。その後、1 つまたは複数の個々のノードに対して異なる設定を指定することで、グローバル設定を上書きできます。例：
+
[listing]
----
CLIENT_NETWORK_MTU = 8192
----
* *PORT_REMAP*: ノードが内部グリッドノード通信または外部通信に使用するポートを再マッピングします。エンタープライズネットワークポリシーによって StorageGRID が使用する1つ以上のポートが制限されている場合、ポートの再マッピングが必要です。StorageGRID が使用するポートの一覧については、link:../network/index.html["ネットワーク構築ガイドライン"] の内部グリッドノード通信および外部通信を参照してください。
+

NOTE: ロードバランサーのエンドポイントを設定するために使用する予定のポートを再マッピングしないでください。

+

NOTE: PORT_REMAPのみが設定されている場合、指定したマッピングは受信通信と送信通信の両方に使用されます。PORT_REMAP_INBOUNDも指定されている場合、PORT_REMAPは送信通信にのみ適用されます。

+
使用されるフォーマットは次のとおりです： `_network type/protocol/default port used by grid node/new port_`ここで、ネットワークタイプはグリッド、管理、またはクライアントであり、プロトコルは tcp または udp です。

+
次に例を示します。

+
[listing]
----
PORT_REMAP = client/tcp/18082/443
----
+
この設定例を単独で使用した場合、グリッドノードの受信通信と送信通信の両方が、ポート18082からポート443に対称的にマッピングされます。PORT_REMAP_INBOUNDと組み合わせて使用すると、この設定例では、ポート18082からの送信通信をポート443にマッピングします。

+
カンマ区切りのリストを使用して、複数のポートを再マッピングすることもできます。

+
次に例を示します。

+
[listing]
----
PORT_REMAP = client/tcp/18082/443, client/tcp/18083/80
----
* *PORT_REMAP_INBOUND*：指定されたポートの受信通信を再マッピングします。PORT_REMAP_INBOUNDを指定してもPORT_REMAPの値を指定しない場合、そのポートの送信通信は変更されません。
+

NOTE: ロードバランサーのエンドポイントを設定するために使用する予定のポートを再マッピングしないでください。

+
使用されるフォーマットは次のとおりです： `_network type_/_protocol/_default port used by grid node_/_new port_`ここで、ネットワークタイプはグリッド、管理、またはクライアントであり、プロトコルは tcp または udp です。

+
次に例を示します。

+
[listing]
----
PORT_REMAP_INBOUND = client/tcp/443/18082
----
+
この例では、ポート443に送信されたトラフィックを内部ファイアウォールを通過させ、グリッドノードがS3リクエストを待機しているポート18082に転送します。

+
カンマ区切りのリストを使用して、複数の受信ポートを再マッピングすることもできます。

+
次に例を示します。

+
[listing]
----
PORT_REMAP_INBOUND = grid/tcp/3022/22, admin/tcp/3022/22
----
* *TEMPORARY_PASSWORD_TYPE*：ノードがグリッドに参加する前に、VMコンソールまたは StorageGRID インストール API へのアクセス時、あるいは SSH の使用時に使用する一時インストールパスワードのタイプ。
+

TIP: 全てのノードまたはほとんどのノードが同じタイプの一時インストールパスワードを使用する場合は、グローバルパラメータセクションでそのタイプを指定してください。次に、必要に応じて個々のノードに異なる設定を適用します。例えば、*カスタムパスワードを使用する*をグローバルに選択した場合、*CUSTOM_TEMPORARY_PASSWORD=<password>* を使用して各ノードのパスワードを設定できます。

+
*TEMPORARY_PASSWORD_TYPE* は、以下のいずれかになります。

+
** *ノード名を使用する*：ノード名は一時的なインストールパスワードとして使用され、VMコンソール、StorageGRID インストール API、および SSH へのアクセスを提供します。
** *パスワードを無効にする*：一時的なインストールパスワードは使用されません。インストールの問題をデバッグするために VM にアクセスする必要がある場合は、link:troubleshooting-installation-issues.html["インストールに関する問題のトラブルシューティング"]を参照してください。
** *カスタムパスワードを使用する*：*CUSTOM_TEMPORARY_PASSWORD=<password>* で指定された値は、一時的なインストールパスワードとして使用され、VMコンソール、StorageGRID インストールAPI、およびSSHへのアクセスを提供します。
+

TIP: オプションとして、*TEMPORARY_PASSWORD_TYPE* パラメーターを省略して、*CUSTOM_TEMPORARY_PASSWORD=<password>* のみを指定することもできます。



* *CUSTOM_TEMPORARY_PASSWORD=<password>* オプション。VM コンソール、StorageGRID インストール API、および SSH にアクセスする際にインストール中に使用する一時パスワード。*TEMPORARY_PASSWORD_TYPE* が *Use node name* または *Disable password* に設定されている場合は無視されます。




==== ノード固有のパラメータ

各ノードは、設定ファイル内のそれぞれ独立したセクションに格納されています。各ノードには以下の設定が必要です：

* セクションの見出しは、Grid Managerに表示されるノード名を定義します。ノードのオプションパラメータである NODE_NAME を指定することで、その値を上書きできます。
* *NODE_TYPE*：VM_Admin_Node、VM_Storage_Node、またはVM_API_Gateway_Node
* *STORAGE_TYPE*：combined、data、またはmetadata。ストレージノードのこのオプションパラメータは、指定されていない場合、デフォルトで combined（データとメタデータ）になります。詳細については、link:../primer/what-storage-node-is.html#types-of-storage-nodes["ストレージノードの種類"]を参照してください。
* *GRID_NETWORK_IP*：グリッドネットワーク上のノードのIPアドレス。
* *ADMIN_NETWORK_IP*：管理ネットワーク上のノードのIPアドレス。ノードが管理ネットワークに接続されており、かつ ADMIN_NETWORK_CONFIG が STATIC に設定されている場合にのみ必要です。
* *CLIENT_NETWORK_IP*：クライアントネットワーク上のノードの IP アドレス。ノードがクライアントネットワークに接続されており、かつこのノードの CLIENT_NETWORK_CONFIG が STATIC に設定されている場合にのみ必要です。
* *ADMIN_IP*: グリッドネットワーク上のプライマリ管理ノードのIPアドレス。プライマリ管理ノードのGRID_NETWORK_IPとして指定した値を使用してください。このパラメータを省略した場合、ノードはmDNSを使用してプライマリ管理ノードのIPアドレスを検出しようとします。詳細については、link:how-grid-nodes-discover-primary-admin-node.html["グリッドノードがプライマリ管理ノードを検出する方法"]を参照してください。
+

NOTE: プライマリ管理ノードの場合、ADMIN_IP パラメータは無視されます。

* グローバルに設定されていないパラメータ。例えば、ノードが管理ネットワークに接続されていて、ADMIN_NETWORK パラメータをグローバルに指定していない場合、そのノードに対してこれらのパラメータを指定する必要があります。


.プライマリ管理ノード
プライマリ管理ノードには、以下の追加設定が必要です。

* *NODE_TYPE*：VM_Admin_Node
* *ADMIN_ROLE*：プライマリ


この例のエントリは、3つのネットワークすべてに存在するプライマリ管理ノードに関するものです。

[listing]
----
[DC1-ADM1]
  ADMIN_ROLE = Primary
  NODE_TYPE = VM_Admin_Node
  TEMPORARY_PASSWORD_TYPE = Use custom password
  CUSTOM_TEMPORARY_PASSWORD = Passw0rd

  GRID_NETWORK_IP = 10.1.0.2
  ADMIN_NETWORK_IP = 10.3.0.2
  CLIENT_NETWORK_IP = 10.4.0.2
----
プライマリ管理ノードでは、以下の追加設定はオプションです。

* *DISK*: デフォルトでは、管理ノードには監査およびデータベース使用のために200 GBのハードディスクが2台追加で割り当てられます。DISK パラメータを使用すると、これらの設定値を増やすことができます。例：
+
[listing]
----
DISK = INSTANCES=2, CAPACITY=300
----



NOTE: 管理ノードの場合、INSTANCES は常に 2 でなければなりません。

.ストレージ ノード
ストレージノードには、以下の追加設定が必要です。

* *NODE_TYPE*：VM_Storage_Node
+
この例のエントリは、グリッドネットワークと管理ネットワークには接続されているが、クライアントネットワークには接続されていないストレージノードに関するものです。このノードは、ADMIN_IP設定を使用して、グリッドネットワーク上のプライマリ管理ノードのIPアドレスを指定します。

+
[listing]
----
[DC1-S1]
  NODE_TYPE = VM_Storage_Node

  GRID_NETWORK_IP = 10.1.0.3
  ADMIN_NETWORK_IP = 10.3.0.3

  ADMIN_IP = 10.1.0.2
----
+
この2番目の例は、クライアントネットワーク上のストレージノードに関するもので、顧客の企業ネットワークポリシーでは、S3クライアントアプリケーションはポート80または443のいずれかを使用してのみストレージノードにアクセスすることが許可されていると規定されています。この設定例のファイルでは、PORT_REMAPを使用して、ストレージノードがポート443でS3メッセージを送受信できるようにしています。

+
[listing]
----
[DC2-S1]
  NODE_TYPE = VM_Storage_Node

  GRID_NETWORK_IP = 10.1.1.3
  CLIENT_NETWORK_IP = 10.4.1.3
  PORT_REMAP = client/tcp/18082/443

  ADMIN_IP = 10.1.0.2
----
+
最後の例では、ポート22からポート3022へのSSHトラフィックの対称的なリマッピングを作成しますが、受信トラフィックと送信トラフィックの両方の値を明示的に設定しています。

+
[listing]
----
[DC1-S3]
  NODE_TYPE = VM_Storage_Node

  GRID_NETWORK_IP = 10.1.1.3

  PORT_REMAP = grid/tcp/22/3022
  PORT_REMAP_INBOUND = grid/tcp/3022/22

  ADMIN_IP = 10.1.0.2
----


ストレージノードには、以下の追加設定がオプションで用意されています。

* *DISK*: デフォルトでは、ストレージノードにはRangeDBで使用するために4 TBのディスクが3つ割り当てられます。これらの設定値は、DISKパラメータで増やすことができます。例えば：
+
[listing]
----
DISK = INSTANCES=16, CAPACITY=4096
----
* *STORAGE_TYPE*：デフォルトでは、すべての新しいストレージノードは、オブジェクトデータとメタデータの両方を保存するように構成されており、これは_combined_ストレージノードと呼ばれます。STORAGE_TYPE パラメータを使用すると、ストレージノードの種類を変更して、データのみまたはメタデータのみを保存するように設定できます。例：
+
[listing]
----
STORAGE_TYPE = data
----


.ゲートウェイ ノード
ゲートウェイノードには、以下の追加設定が必要です。

* *NODE_TYPE*：VM_API_Gateway


このサンプルエントリは、3つのネットワークすべてにおけるゲートウェイノードの例を示しています。この例では、設定ファイルのグローバルセクションにクライアントネットワークパラメータが指定されていないため、ノードに対して指定する必要があります：

[listing]
----
[DC1-G1]
  NODE_TYPE = VM_API_Gateway

  GRID_NETWORK_IP = 10.1.0.5
  ADMIN_NETWORK_IP = 10.3.0.5

  CLIENT_NETWORK_CONFIG = STATIC
  CLIENT_NETWORK_TARGET = SG Client Network
  CLIENT_NETWORK_MASK = 255.255.255.0
  CLIENT_NETWORK_GATEWAY = 10.4.0.1
  CLIENT_NETWORK_IP = 10.4.0.5

  ADMIN_IP = 10.1.0.2
----
.非プライマリ管理ノード
プライマリ以外の管理ノードには、以下の追加設定が必要です。

* *NODE_TYPE*：VM_Admin_Node
* *ADMIN_ROLE*：非プライマリ


この例のエントリは、クライアントネットワーク上にない、プライマリではない管理ノードに関するものです。

[listing]
----
[DC2-ADM1]
  ADMIN_ROLE = Non-Primary
  NODE_TYPE = VM_Admin_Node

  GRID_NETWORK_TARGET = SG Grid Network
  GRID_NETWORK_IP = 10.1.0.6
  ADMIN_NETWORK_IP = 10.3.0.6

  ADMIN_IP = 10.1.0.2
----
以下の追加設定は、プライマリ以外の管理ノードではオプションです。

* *DISK*: デフォルトでは、管理ノードには監査およびデータベース使用のために200 GBのハードディスクが2台追加で割り当てられます。DISK パラメータを使用すると、これらの設定値を増やすことができます。例：
+
[listing]
----
DISK = INSTANCES=2, CAPACITY=300
----



NOTE: 管理ノードの場合、INSTANCES は常に 2 でなければなりません。



[[run-the-bash-script]]
== Bashスクリプトを実行する

変更した Bash スクリプトと deploy-vsphere-ovftool.ini 構成ファイルを使用して、VMware vSphere への StorageGRID ノードのデプロイを自動化できます。 `deploy-vsphere-ovftool.sh`

.開始する前に
ご使用の環境用にdeploy-vsphere-ovftool.ini構成ファイルを作成しました。

Bashスクリプトのヘルプは、ヘルプコマンドを入力することで利用できます（(`-h/--help`）。例：

[listing]
----
./deploy-vsphere-ovftool.sh -h
----
または

[listing]
----
./deploy-vsphere-ovftool.sh --help
----
.手順
. Bashスクリプトを実行するために使用しているLinuxマシンにログインしてください。
. インストールアーカイブを展開したディレクトリに移動します。
+
次に例を示します。

+
[listing]
----
cd StorageGRID-Webscale-version/vsphere
----
. すべてのグリッドノードをデプロイするには、環境に適したオプションを指定してBashスクリプトを実行してください。
+
次に例を示します。

+
[listing]
----
./deploy-vsphere-ovftool.sh --username=user --password=pwd ./deploy-vsphere-ovftool.ini
----
. グリッドノードのデプロイがエラーによって失敗した場合は、エラーを解決し、そのノードのみに対してBashスクリプトを再実行してください。
+
次に例を示します。

+
[listing]
----
./deploy-vsphere-ovftool.sh --username=user --password=pwd --single-node="DC1-S3" ./deploy-vsphere-ovftool.ini
----


各ノードのステータスが「Passed」になった時点で、デプロイは完了です。

[listing]
----

+-----------------------------+----------+----------------------+
| DC1-ADM1                    |        1 | Passed               |
| DC1-G1                      |        1 | Passed               |
| DC1-S1                      |        1 | Passed               |
| DC1-S2                      |        1 | Passed               |

[[automate-the-configuration-of-storagegrid]]
== StorageGRID の設定を自動化する

グリッドノードをデプロイした後、StorageGRID システムの設定を自動化できます。

.開始する前に
* インストールアーカイブ内の以下のファイルの場所を確認しておいてください。
+
[cols="1a,1a"]
|===
| ファイル名 | 説明 


| configure-storagegrid.py  a| 
設定を自動化するために使用されるPythonスクリプト



| configure-storagegrid.sample.json  a| 
スクリプトで使用する設定ファイルの例



| configure-storagegrid.blank.json  a| 
スクリプトで使用するための空の設定ファイル

|===
* あなたは `configure-storagegrid.json`設定ファイルを作成しました。このファイルを作成するには、サンプル設定ファイル(`configure-storagegrid.sample.json`）または空の設定ファイル(`configure-storagegrid.blank.json`）を変更してください。



CAUTION: 変更後の `configure-storagegrid.json`設定ファイルのパスワードセクションから管理パスワードとプロビジョニングパスフレーズを安全な場所に保存してください。これらのパスワードは、インストール、拡張、およびメンテナンスの手順に必要です。変更後の `configure-storagegrid.json`設定ファイルのバックアップも作成し、安全な場所に保管してください。

.タスク概要
 `configure-storagegrid.py` Python スクリプトと  `configure-storagegrid.json` グリッド構成ファイルを使用して、StorageGRID システムの構成を自動化できます。


NOTE: グリッドマネージャーまたはインストールAPIを使用してシステムを設定することもできます。

.手順
. Pythonスクリプトを実行するために使用しているLinuxマシンにログインします。
. インストールアーカイブを展開したディレクトリに移動します。
+
次に例を示します。

+
[listing]
----
cd StorageGRID-Webscale-version/platform
----
+
 `platform`は、debs、rpms、またはvsphereです。

. Pythonスクリプトを実行し、作成した設定ファイルを使用してください。
+
次に例を示します。

+
[listing]
----
./configure-storagegrid.py ./configure-storagegrid.json --start-install
----


.結果
リカバリパッケージ `.zip`ファイルは設定プロセス中に生成され、インストールおよび設定プロセスを実行しているディレクトリにダウンロードされます。1つ以上のグリッドノードに障害が発生した場合にStorageGRIDシステムを復旧できるよう、リカバリパッケージファイルをバックアップする必要があります。たとえば、セキュアなバックアップ済みネットワーク上の場所と、セキュアなクラウドストレージの場所にコピーしてください。


CAUTION: リカバリパッケージファイルには暗号化キーとパスワードが含まれており、これらを使用して StorageGRID システムからデータを取得できるため、このファイルは保護する必要があります。

ランダムなパスワードを生成するように指定した場合は、 `Passwords.txt`ファイルを開き、StorageGRID システムへのアクセスに必要なパスワードを確認してください。

[listing]
----

#####           ./sgws-recovery-package-994078-rev1.zip          #####
#####   Safeguard this file as it will be needed in case of a    #####
#####                 StorageGRID node recovery.                 #####
######################################################################
----
確認メッセージが表示されたら、StorageGRID システムのインストールと設定が完了しています。

[listing]
----
StorageGRID has been configured and installed.
----
