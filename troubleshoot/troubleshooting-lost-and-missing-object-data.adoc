= StorageGRIDで紛失したオブジェクトデータと行方不明のオブジェクトデータについて学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
オブジェクトは、クライアントアプリケーションからの読み取り要求、複製されたオブジェクトデータのバックグラウンド検証、ILMの再評価、ストレージノードの復旧中のオブジェクトデータの復元など、いくつかの理由で取得される場合があります。

StorageGRIDシステムは、オブジェクトのメタデータに含まれる位置情報を使用して、オブジェクトをどの場所から取得するかを決定します。オブジェクトのコピーが想定される場所に見つからない場合、ILMポリシーにオブジェクトのコピーを2つ以上作成するルールが含まれていることを前提として、システムはシステム内の別の場所からオブジェクトの別のコピーを取得しようとします。

この取得が成功した場合、StorageGRID システムは、不足しているオブジェクトのコピーを置き換えます。それ以外の場合は、以下のように *Objects potentially lost* アラートがトリガーされます。

* 複製されたコピーの場合、別のコピーを取得できないときは、オブジェクトは失われたとみなされ、アラートがトリガーされます。
* 消去符号化されたコピーの場合、想定される場所からコピーを取得できない場合、別の場所からコピーを取得する試みが行われる前に、破損コピー検出（ECOR）属性が1つ増加します。他にコピーが見つからない場合、アラートがトリガーされます。


*オブジェクトが失われた可能性あり*アラートが発生した場合は、直ちに調査を行い、損失の根本原因を特定するとともに、オブジェクトがオフライン状態、または現在利用できないストレージノードにまだ存在している可能性があるかどうかを判断する必要があります。link:../troubleshoot/investigating-potentially-lost-objects.html["紛失の可能性があるオブジェクトを調査する"]を参照してください。オブジェクト損失アラートは、念のため誤ってトリガーされる場合があります。

コピーのないオブジェクトデータが失われた場合、復旧手段はありません。ただし、既知の失われたオブジェクトが新たに失われたオブジェクトを隠蔽しないようにするために、link:../troubleshoot/investigating-potentially-lost-objects.html#reset-lost-obj-count["紛失した可能性のあるオブジェクトのカウンターをリセットします"]必要があります。
