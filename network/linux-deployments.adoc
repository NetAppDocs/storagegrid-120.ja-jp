= StorageGRID Linuxデプロイメントのネットワーク構成
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
効率性、信頼性、セキュリティのために、StorageGRID システムは Linux 上でコンテナエンジンの集合体として動作します。コンテナエンジン関連のネットワーク設定は、StorageGRID システムでは必要ありません。

コンテナのネットワーク インターフェイスには、VLANや仮想イーサネット（veth）ペアなどの非ボンディングデバイスを使用してください。ノード設定ファイルで、このデバイスをネットワーク インターフェイスとして指定してください。


CAUTION: ボンドデバイスやブリッジデバイスをコンテナのネットワーク インターフェイスとして直接使用しないでください。そうすると、コンテナ名前空間内でボンドデバイスとブリッジデバイスを macvlan で使用する際にカーネルに問題が発生するため、ノードの起動が妨げられる可能性があります。

link:../swnodes/index.html["インストール手順"]を参照してください。



[[host-network-configuration-for-container-engine-deployments]]
== コンテナエンジンのデプロイにおけるホストネットワーク構成

コンテナエンジンプラットフォームへの StorageGRID のデプロイを開始する前に、各ノードが使用するネットワーク（グリッド、管理、クライアント）を決定します。各ノードのネットワークインターフェイスが正しい仮想または物理ホスト インターフェイスに構成されていること、および各ネットワークに十分な帯域幅があることを確認する必要があります。



[[physical-hosts]]
=== 物理ホスト

グリッドノードをサポートするために物理ホストを使用している場合：

* すべてのホストが各ノード インターフェイスに同じホスト インターフェイスを使用していることを確認してください。この戦略により、ホスト構成が簡素化され、将来のノード移行が可能になります。
* 物理ホスト自体のIPアドレスを取得します。
+

NOTE: ホスト上の物理インターフェースは、ホスト自体と、ホスト上で動作する1つ以上のノードによって使用できます。このインターフェースを使用するホストまたはノードに割り当てられるIPアドレスは、すべて一意でなければなりません。ホストとノードはIPアドレスを共有できません。

* ホストに対して必要なポートを開放してください。
* StorageGRID で VLAN インターフェイスを使用する場合、ホストには目的の VLAN へのアクセスを提供する 1 つ以上のトランクインターフェイスが必要です。これらのインターフェイスは、eth0、eth2、または追加のインターフェイスとしてノードコンテナに渡すことができます。トランクインターフェイスまたはアクセスインターフェイスを追加するには、以下を参照してください。
+
** *Linux（ノードをインストールする前）*：link:../swnodes/creating-node-configuration-files.html["ノード設定ファイルを作成する"]
** *Linux（ノードのインストール後）*：link:../maintain/linux-adding-trunk-or-access-interfaces-to-node.html["ノードにトランクインターフェースまたはアクセスインターフェースを追加する"]





NOTE: 「Linux」とは、RHEL、Ubuntu、またはDebianのいずれかの環境を指します。サポートされているバージョンの一覧については、 https://imt.netapp.com/matrix/#welcome["NetApp Interoperability Matrix Tool（IMT）"^]を参照してください。

NOTE: この表には、共有ストレージへのアクセスに必要なSAN帯域幅は含まれていません。イーサネット経由でアクセスする共有ストレージ（iSCSIまたはFCoE）を使用する場合は、十分なSAN帯域幅を確保するために、各ホストに個別の物理インターフェイスをプロビジョニングする必要があります。ボトルネックの発生を避けるため、特定のホストのSAN帯域幅は、そのホスト上で稼働するすべてのストレージノードのストレージノード ネットワーク帯域幅の合計とほぼ一致させる必要があります。

この表を使用して、そのホストで実行する予定の StorageGRID ノードの数と種類に基づいて、各ホストにプロビジョニングするネットワーク インターフェイスの最小数を決定します。

例えば、1台のホスト上で1つの管理ノード、1つのゲートウェイノード、および1つのストレージノードを実行する場合：

* 管理ノード上でグリッドネットワークと管理ネットワークを接続します（10 + 1 = 11 Gbps が必要）
* ゲートウェイノード上でグリッドネットワークとクライアントネットワークを接続します（10 + 10 = 20 Gbps が必要）
* ストレージノード上でグリッドネットワークを接続します（10 Gbps が必要）。


このシナリオでは、最低でも 11 + 20 + 10 = 41 Gbps のネットワーク帯域幅を提供する必要があります。これは、2 つの 40 Gbps インターフェイスまたは 5 つの 10 Gbps インターフェイスで満たすことができ、これらをトランクに集約して、ホストを含む物理データセンターにローカルなグリッド、管理、およびクライアントサブネットを伝送する 3 つ以上の VLAN で共有することができます。

StorageGRID クラスターのホスト上で物理およびネットワーク リソースを設定するための推奨方法については、link:../swnodes/configuring-host-network.html["ホストネットワークの設定"] を参照してください。
