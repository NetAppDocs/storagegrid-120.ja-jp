= StorageGRID のネットワーク固有の要件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRIDの各ネットワークタイプの要件に従ってください。



[[network-gateways-and-routers]]
== ネットワークゲートウェイとルーター

* 設定されている場合、特定のネットワークのゲートウェイは、そのネットワークのサブネット内に存在する必要があります。
* 静的アドレス指定を使用してインターフェースを設定する場合は、0.0.0.0以外のゲートウェイアドレスを指定する必要があります。
* ゲートウェイがない場合は、ゲートウェイアドレスをネットワーク インターフェイスの IP アドレスに設定することをお勧めします。




[[subnets]]
== サブネット


NOTE: 各ネットワークは、ノード上の他のネットワークと重複しない独自のサブネットに接続する必要があります。

グリッドマネージャーは、デプロイ時に以下の制限事項を適用します。これらは、ネットワーク展開前の計画策定を支援するために提供されています。

* ネットワーク IP アドレスのサブネットマスクは、255.255.255.254 または 255.255.255.255 （CIDR 表記では /31 または /32）であってはなりません。
* ネットワーク インターフェイスの IP アドレスとサブネット マスク（CIDR）で定義されるサブネットは、同じノードに設定されている他のインターフェイスのサブネットと重複してはなりません。
* いずれのノードのグリッドネットワーク、管理ネットワーク、またはクライアントネットワークにおいても、以下の IPv4 アドレスを含むサブネットを使用しないでください。
+
** 192,168,130,101
** 192,168,130,121
** 192,168,131,101
** 192,168,131,121
** 192,168,130,102
** 192,168,130,122
** 192,168,131,102
** 192,168,131,122
** 198.51.100.2
** 198.51.100.4


+
例えば、どのノードのグリッドネットワーク、管理ネットワーク、またはクライアントネットワークにも、以下のサブネット範囲を使用しないでください。

+
** 192.168.130.0/24 は、このサブネット範囲に IP アドレス 192.168.130.101 と 192.168.130.102 が含まれているためです。
** 192.168.131.0/24 は、このサブネット範囲に IP アドレス 192.168.131.101 と 192.168.131.102 が含まれているためです。
** 198.51.100.0/24 は、このサブネット範囲に IP アドレス 198.51.100.2 と 198.51.100.4 が含まれているためです。


* 各ノードのグリッドネットワークサブネットは GNSL に含める必要があります。
* 管理ネットワークのサブネットは、グリッドネットワークのサブネット、クライアントネットワークのサブネット、またはGNSL内のどのサブネットとも重複してはなりません。
* AESL内のサブネットは、GNSL内のサブネットと重複することはできません。
* クライアントネットワークのサブネットは、グリッドネットワークのサブネット、管理ネットワークのサブネット、GNSL内のいずれかのサブネット、またはAESL内のいずれかのサブネットと重複することはできません。




[[grid-network]]
== グリッド ネットワーク

* デプロイ時には、各グリッドノードはグリッドネットワークに接続され、ノードのデプロイ時に指定したネットワーク構成を使用してプライマリ管理ノードと通信できる必要があります。
* 通常のグリッド運用時、各グリッドノードは、グリッドネットワークを介して他のすべてのグリッドノードと通信できる必要があります。
+

NOTE: グリッドネットワークは、各ノード間で直接ルーティング可能である必要があります。ノード間のネットワークアドレス変換（NAT）はサポートされていません。

* グリッドネットワークが複数のサブネットで構成されている場合は、それらをグリッドネットワークサブネットリスト（GNSL）に追加します。GNSL内の各サブネットについて、すべてのノード上に静的ルートが作成されます。
* グリッドネットワークインターフェイスがVLANインターフェイスをサポートするためにトランクとして構成されている場合、トランクのネイティブVLANは、グリッドネットワークトラフィックに使用されるVLANでなければなりません。すべてのグリッドノードは、トランクネイティブVLAN経由でアクセス可能である必要があります。




[[admin-network]]
== 管理者ネットワーク

管理者ネットワークはオプションです。管理者ネットワークを構成する場合は、以下の要件とガイドラインに従ってください。

管理ネットワークの一般的な用途には、管理接続、AutoSupport、KMS、およびNTP、DNS、LDAPなどの重要なサーバーへの接続（これらの接続がグリッドネットワークまたはクライアントネットワーク経由で提供されていない場合）が含まれます。


NOTE: 管理ネットワークとAESLは、必要なネットワークサービスとクライアントにアクセスできる限り、各ノードに固有のものにすることができます。


NOTE: 外部サブネットからの受信接続を有効にするには、管理ネットワーク上に少なくとも1つのサブネットを定義する必要があります。AESL内の各サブネットに対して、各ノード上で静的ルートが自動的に生成されます。



[[client-network]]
== クライアント ネットワーク

クライアントネットワークはオプションです。クライアントネットワークを構成する予定がある場合は、以下の点に注意してください。

* クライアントネットワークは、S3クライアントからのトラフィックをサポートするように設計されています。設定されている場合、クライアントネットワークゲートウェイはノードのデフォルトゲートウェイになります。
* クライアントネットワークを使用する場合、明示的に設定されたロードバランサーエンドポイントでのみ受信クライアントトラフィックを受け入れることで、悪意のある攻撃からStorageGRIDを保護できます。link:../admin/configuring-load-balancer-endpoints.html["ロードバランサーのエンドポイントを設定する"]を参照してください。
* クライアントネットワークインターフェースがVLANインターフェースをサポートするためにトランクとして構成されている場合は、クライアントネットワークインターフェース（eth2）の構成が必要かどうかを検討してください。設定されている場合、クライアントネットワークのトラフィックは、スイッチで設定されているトランクネイティブVLANを経由して流れます。
