= StorageGRID の Grid Network トポロジ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
最もシンプルなネットワークトポロジーは、グリッドネットワークのみを構成することで作成できます。

グリッドネットワークを設定する際には、各グリッドノードのeth0インターフェースに対して、ホストIPアドレス、サブネットマスク、およびゲートウェイIPアドレスを設定します。

設定時には、すべてのグリッドネットワークサブネットをグリッドネットワークサブネットリスト（GNSL）に追加する必要があります。このリストには、すべてのサイトのすべてのサブネットが含まれており、NTP、DNS、LDAPなどの重要なサービスへのアクセスを提供する外部サブネットも含まれる場合があります。

インストール時に、グリッドネットワークインターフェイスはGNSL内のすべてのサブネットに対して静的ルートを適用し、グリッドネットワークゲートウェイが設定されている場合は、ノードのデフォルトルートをそのゲートウェイに設定します。クライアントネットワークが存在せず、グリッドネットワークゲートウェイがノードのデフォルトルートである場合、GNSLは不要です。グリッド内の他のすべてのノードへのホストルートも生成されます。

この例では、S3クライアントのリクエストや管理・保守機能に関連するトラフィックを含め、すべてのトラフィックが同じネットワークを共有します。


NOTE: このトポロジーは、外部からアクセスできない単一サイトの展開、コンセプトの実証またはテスト展開、あるいはサードパーティのロードバランサーがクライアントアクセス境界として機能する場合に適しています。可能な限り、グリッドネットワークは内部トラフィック専用に使用してください。管理ネットワークとクライアントネットワークの両方には、外部からのトラフィックを内部サービスにブロックする追加のファイアウォール制限が設定されています。外部クライアントのトラフィックにグリッドネットワークを使用することはサポートされていますが、この使用方法では保護層が少なくなります。
