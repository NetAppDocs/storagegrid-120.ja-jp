= StorageGRIDの外部通信
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
クライアントは、コンテンツを取り込み、取得するためにグリッドノードと通信する必要があります。使用されるポートは、選択されたオブジェクトストレージプロトコルによって異なります。これらのポートはクライアントからアクセス可能である必要があります。



[[restricted-access-to-ports]]
== ポートへのアクセス制限

企業ネットワークポリシーによっていずれかのポートへのアクセスが制限されている場合は、以下のいずれかの操作を行ってください。

* link:../admin/configuring-load-balancer-endpoints.html["ロードバランサーのエンドポイント"]を使用して、ユーザー定義ポートへのアクセスを許可します。
* ノードをデプロイする際にポートを再マッピングします。ただし、ロードバランサーのエンドポイントを再マッピングしないでください。StorageGRID ノードのポート再マッピングに関する情報を参照してください：



NOTE: ポート再マッピングのサポートは非推奨となり、今後のリリースで削除されます。再マッピングされたポートを削除するには、link:../maintain/removing-port-remaps.html["StorageGRID アプライアンスのポートリマップを削除する"]またはlink:../maintain/removing-port-remaps-on-bare-metal-hosts.html["ベアメタルホスト上のポートリマップを削除する"]を参照してください。

* link:../swnodes/creating-node-configuration-files.html["Red Hat Enterprise Linux 上の StorageGRID のポート再マップキー"]
* link:../swnodes/deploying-storagegrid-node-as-virtual-machine.html#vmware-remap-ports["VMware 上の StorageGRID のポートを再マッピングする"]
* https://docs.netapp.com/us-en/storagegrid-appliances/installconfig/optional-remapping-network-ports-for-appliance.html["オプション：アプライアンスのネットワークポートを再マッピングする"^]
