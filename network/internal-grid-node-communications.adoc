= StorageGRID の内部グリッド ノード通信
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID の内部ファイアウォールは、グリッドネットワーク上の特定のポートへの着信接続を許可します。ロードバランサーのエンドポイントによって定義されたポートでも接続を受け付けます。


NOTE: NetApp では、グリッドノード間でインターネット制御メッセージプロトコル（ICMP）トラフィックを有効にすることを推奨します。ICMP トラフィックを許可することで、グリッドノードに接続できない場合のフェイルオーバーパフォーマンスを向上させることができます。

ICMPと表に記載されているポートに加えて、StorageGRIDは仮想ルーター冗長プロトコル（VRRP）を使用します。VRRPは、IPプロトコル番号112を使用するインターネットプロトコルです。StorageGRIDはVRRPをユニキャストモードでのみ使用します。VRRPが必要なのは、link:../admin/managing-high-availability-groups.html["高可用性グループ"]が設定されている場合のみです。



[[guidelines-for-linux-based-nodes]]
== Linuxベースのノードに関するガイドライン

企業ネットワークポリシーによってこれらのポートへのアクセスが制限されている場合は、展開構成パラメータを使用して展開時にポートを再マッピングできます。ポートのリマッピングとデプロイメント構成パラメータの詳細については、link:../swnodes/index.html["ソフトウェアベースのノードへの StorageGRID のインストール"]を参照してください。


NOTE: ポート再マッピングのサポートは非推奨となり、今後のリリースで削除されます。再マッピングされたポートを削除するには、link:../maintain/removing-port-remaps-on-bare-metal-hosts.html["ベアメタルホスト上のポートリマップを削除する"]を参照してください。



[[guidelines-for-vmware-based-nodes]]
== VMwareベースのノードに関するガイドライン

VMwareネットワークの外部でファイアウォールの制限を定義する必要がある場合にのみ、以下のポートを設定してください。

エンタープライズ ネットワーク ポリシーでこれらのポートへのアクセスが制限されている場合は、VMware vSphere Web クライアントを使用してノードをデプロイする際にポートを再マッピングするか、グリッド ノードのデプロイを自動化する際に構成ファイルの設定を使用することができます。ポートのリマッピングとデプロイメント構成パラメータの詳細については、link:../swnodes/index.html["VMware への StorageGRID のインストール"]の手順を参照してください。


NOTE: ポート再マッピングのサポートは非推奨となり、今後のリリースで削除されます。再マッピングされたポートを削除するには、link:../maintain/removing-port-remaps-on-bare-metal-hosts.html["ベアメタルホスト上のポートリマップを削除する"]を参照してください。



[[guidelines-for-appliance-nodes]]
== アプライアンスノードに関するガイドライン

企業のネットワークポリシーによりこれらのポートへのアクセスが制限されている場合は、StorageGRID アプライアンスインストーラを使用してポートを再マッピングできます。参照： https://docs.netapp.com/us-en/storagegrid-appliances/installconfig/optional-remapping-network-ports-for-appliance.html["オプション：アプライアンスのネットワークポートを再マッピングする"^]


NOTE: ポート再マッピングのサポートは非推奨となり、今後のリリースで削除されます。再マッピングされたポートを削除するには、link:../maintain/removing-port-remaps.html["StorageGRID アプライアンスのポートリマップを削除する"]を参照してください。
